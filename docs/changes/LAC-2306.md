## Source change

The native prompt previously separated the existence check from model-written
setup, published `inputs.sh` before environment resolution and context, and
made recovery depend on a tool result for whatever the model appended. AMA
now renders a versioned setup command into the per-attempt scratch directory.
It checks the harness, pins the starting head, resolves the launch environment
and reads context. It uses the existing CLI entry points and timeout budgets.
Staging keeps partial input and context files private. The starting head
survives a later step failure, and a concurrent setup invocation returns 75
without another read or audit. Bootstrap emits its stage and status on failure.
The model waits for the one command's result, then reads the context and full
review. The bootstrap has no source, merge lease or retry ledger write authority.

## Agent OS handoff and runtime acceptance

Root should take the native result-collection investigation to the Agent OS
worker-pool owner. Start from the rollout's native session ID and
`cwp_dispatch/boundary_steer.py` (`subprocess.run` and `emit_policy`). Correlate
shell launch, direct child exit, any surviving pipe writers, collector EOF
and completion publication. `cwp_dispatch/progress_health.py` and
`dead_closer_custody.py` own process evidence and terminal reconciliation.
Compare the complete rollout stream with the stdout-only timeline in
`cwp_dispatch/command_timing.py` and the queue state from `native_exec_steer.py`.
Preserve task/run/session identity, exit status, and original usage at each
boundary. Diagnose a stuck result only after separating collector delay from
an active descendant. The `execution_verdict.py` tool-host-outage path is
for runs whose tool host never answered, which is a different symptom.

Qualify the companion behavior on both sides of that boundary: a slow useful
writer with an open result stream, an exited shell with a missing completion,
a draining descendant, an unreadable or reused identity, and a queued steer
without acknowledgement. Healthy writers retain custody. The replacement
must wait for a fenced terminal receipt covering the exact launch and its
executable scope and retries. Verify a single successor decision and preserved
spend and audit history. The ordinary managed cancellation and source guards
remain the runtime authority. A native dispatch admission receipt records
admission. Runtime acceptance requires observing the loaded source drive
bootstrap and the supervisor reconcile these cases end to end.

## Verification

Before changing source, replayed the archived item 2 Bash payload with all
production paths redirected to offline fixtures. All 20 control runs completed.
With the final lookup held at a controlled read, 20/20 runs exposed final
`inputs.sh` and valid context while the command was still active. With a
fixture collector withholding the result after shell reap, 20/20 exposed the
same guard state. These are deterministic interleavings, not a measured
production incident rate or identification of the native stall mechanism.

The bootstrap regression drives a foreground child through a FIFO for 20
trials. While it waits, a duplicate invocation refuses and the ready inputs
stay absent. The fixture then lets the original child finish with exit 75 and
checks that its process group has drained before starting another attempt.
It also verifies the preserved starting head, missing-script audit and
refusal of partial context output.
