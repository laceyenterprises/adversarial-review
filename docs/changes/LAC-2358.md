# LAC-2358 — Reduce repeated offline closer setup

## Summary

On main `455feaadcb825c62274015bb3f1da2c02cffada8`, Node 22.23.5 reached the
900-second suite deadline with 248 files still queued and eight active. The
log reported 20,145 case outcomes and zero assertion failures. Node 26.10.0
completed 960 files and 22,610 cases in 869.955 seconds with eight workers,
56 skips and zero failures. The earlier run `45520612089` was canceled when
its head was superseded. [Node 22 job](https://github.com/laceyenterprises/adversarial-review/actions/runs/45522292167/job/138897021011) ·
[Node 26 job](https://github.com/laceyenterprises/adversarial-review/actions/runs/45522292167/job/138897020553)

The eight active files had committed estimates between 1.579 and 1.640
seconds. The 20,145 case records matching across the two logs consumed
6,354.438 seconds of overlapping case time on Node 22 and 5,979.203
seconds on Node 26. The work was spread across the queue. These totals
measure observed case costs, including process waits and contention.

Repeated real `ama-check` invocations loaded the full follow-up job and
merge-agent graphs before evaluating a review. The CLI now imports the shared
finding classifiers from their own module and loads the existing follow-up job
reader only when re-proving claimed cycle exhaustion. This removes cold
process work from ordinary evaluations. Every evaluation still runs the same
predicate against the same evidence and uses the same verdict and exit-code
contract. The existing classifier exports remain available to callers. A
static import walk from `bin/ama-check.mjs` on the reproduction head drops
from 363 to about 222 distinct local modules on the non-exhausted path.

The rendered Hammer self-rebase fixtures also reuse identical blob object IDs
while building each private Git seed and create its two initial refs in one
command. Real Git still creates the same commit graph and imports the same
objects into each scratch worktree. Each case still operates on its own copy
of the seed.

## Interface changes

None. Both supported Node majors still select every file on main. The runner
continues to use eight workers, measured order, one exclusive SMV file and a
900-second CI deadline. Per-file compile caches and fixture process isolation
follow the existing runner policy.
