# LAC-2330 — Offline CI fixture startup

## Summary

Three contention cases reuse one Node process per contender across 22 repair
reservation rounds, 30 owner-claim rounds and 20 handoff rounds. Process
launches in those cases fall from 188 to 8. Repair rounds use separate ledger
roots. Queue contenders reopen independent SQLite connections before each
start barrier. The duplicate handoff case still waits for both evidence reads
before releasing either commit. Crash-after-commit evidence still comes
from a dedicated child that exits before acknowledging.

Rendered Hammer validation fixtures replay static fake GitHub responses with
shell and `jq`. The fixtures still cross the executable boundary and capture
each argument. The two quota-defer fixtures retain the dynamic state writer.

Final Comment-only remediation bounds reused worker exchanges and shutdown
waits to 15 seconds. Timeout diagnostics identify the script, contender index,
PID and exchange number; shutdown timeouts kill the child before cleanup.
Claimant disconnect cleanup defers store closure until an active claim finishes
and skips replies after IPC disconnect. Shell replay reports argv-capture
failures explicitly with exit status 97, distinguishing missing or failing `jq`
from a missing route.

## Interface changes

None. The changes are limited to test fixtures and assertions.
