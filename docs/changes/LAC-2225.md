## Interface changes

The close launcher now attempts comment delivery after the controller drains
successfully. The same native launch can retry
`node bin/hammer-closing-comment.mjs OWNER/REPO PR HQ_ROOT` from a fresh shell.
The helper verifies existing durable proof against GitHub and checks the
merge lane and existing comments before posting. It only delivers the closing
comment. Missing optional facts are reported as unrecorded.

The first-review remediation adds the writer to the outbound-body inventory and
checks that the filtered value reaches GitHub's body field. Closeout retries
transient reads and records confirmed delivery beside the merge receipt. A
runtime owner can reconcile pending delivery after launch exit with `--recover`
and the original launch and run IDs. The helper uses the exact-head validation
author rule and recognizes legacy standalone short merge SHAs. Merge attempts
without verified own-merge proof go to operator follow-up.
