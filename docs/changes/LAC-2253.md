# LAC-2253 — qualify the child before testing writer expiry

The hosted Node 26 suite on PR #1955 failed the legacy writer SIGKILL/output
fixture because its 300 ms timer expired before the child installed its signal
handler. A synthetic 450 ms child-startup delay reproduced the unmodified test
in three of three fresh processes.

Both sibling signal fixtures now await an actual child readiness marker and
advance only the parent's deadline timers deterministically. Signal delivery,
partial output, handler flush, grace-period survival and child exit remain real.
The PID marker is published with an atomic rename and validated as a positive
integer greater than one. Marker and exit observation have explicit bounds; a
fixture-only child watchdog prevents leaks on assertion failure.

The first intermediate readiness implementation failed on process 9 of 9;
a bounded-exit refinement failed on process 3 of 3. Inspection found an empty
PID marker being read between file creation and write, which converted to PID 0.
Atomic publication plus nonempty reads and PID validation corrected this. The
final version passed 20 consecutive fresh delayed-start processes, exercising
both signal cases in each process (40 cases). This perturbation is a deterministic
reproducer of the startup assumption, not a measurement of the ordinary CI
failure rate.

Production command timeouts, kill grace, process runner, interfaces and data
models are unchanged. No workflow runner, budget or assertion was waived.
