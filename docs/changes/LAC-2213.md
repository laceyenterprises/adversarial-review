# LAC-2213: retain refused edited-rename boundaries

The edited-rename proof introduced by LAC-2212 rejected invalid structural
proofs, but the caller then evaluated the absent source as an ordinary deletion.
A finding covering the original added file could authorize that deletion and
bypass the move's destination, ancestry, blob and patch requirements.

After the existing identical-blob and finding-authorized move proofs fail,
a source named by an actual rename in the retained authorization history now
fails closed. It cannot fall through to ordinary deletion authorization.
Genuine deletions and retained source files keep their existing behavior.
No public interface, persisted schema, lifecycle state or smoke promise changes.

The existing rename fixture suite reproduced 19 failures before the repair.
Afterward all 254 cases across the rename, primary-change, finding-line and
rebase suites pass, including the negative destination, ancestry and blob cases.
Source review, CI, merge and deployed evaluation remain separate acceptance.
