# LAC-2424 — Preserve insertions across an empty Git diff boundary

## Summary

Agent OS #11645 added one empty line between `mark_client_gone` and the
following comment in `handover.py`. The merge-base comparisons placed the
same protected insertion at base anchors 62 and 63. The source gate treated
the original anchor as a reversal and asked for authorization for line 62.

The preservation check now recognizes this shift across one unchanged empty
base line when the candidate retains the exact inserted lines in order and the
reanchored patch has one extra empty line at the corresponding edge. The check
refuses a shifted match when the candidate also covers a unit from another
protected region, including content replacing blank base lines. It also refuses
nearby protected pure insertions that could shift onto the same candidate.
Exact line comparison retains indentation, string
contents and internal blank lines. Reversal citations keep their original
coordinates and evidence requirements.

## Interface changes

Primary-change refusals can include optional
`missingEvidence.primaryHeadInsertions: { headSha, spans }`, where each span
is `{ filename, start, end }` on the protected head. The summary appends
`. Protected insertion on <sha> at <filename>:<start>-<end>` and a remaining
span count when applicable. These display diagnostics carry no reversal
authority and are excluded from deterministic hammer-stop refusal identity;
the original merge-base `regions` retain that authority.
