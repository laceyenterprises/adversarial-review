# LAC-2218

## Summary

Preserve authenticated submitting identity and live remediation custody across
stale-head cancellation. Own publications survive non-ancestral native rewrites
before produced attestation visibility; failed or pending cancellation keeps the
same in-progress worker reconciliable and posts no false terminal failure.
See [RCA and evidence limits](../postmortems/LAC-2218-follow-up-cancellation-custody.md).

## Interface changes

The existing accepted `hqParentSession` crosses the cancellation CLI boundary
when the monitor has no explicit parent; HQ authorization remains authoritative.
Optional `remediationWorker.cancellationHold` records intended action, reason and
latest attempt time. Active custody now self-loops on cancellation failure or
pending intent instead of transitioning to failed. HEAD history and verified
exact-launch produced attestations are custody evidence only. No configuration,
merge predicate, CI trigger, runner or smoke command changes.
