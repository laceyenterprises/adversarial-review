# LAC-2333 — Preserve published remediation through CI read failures

## Summary

AR #2030 and Agent OS #11477 both published remediation, then received
`stopped (no-progress)` comments while check observation was still pending.
The #2030 worker also reported an HTTP 401 from the bounded check watch.
Once the final-round reconciler independently proves publication, these
reports now retain the source edge and use the existing watcher handoff.
The watcher observes the published head through managed GitHub reads.
An unresolved permission or policy denial retains unknown CI and names
the operator for recovery.

Public witnesses: [AR #2030](https://github.com/laceyenterprises/adversarial-review/pull/2030#issuecomment-7092916408),
[Agent OS #11477](https://github.com/laceyenterprises/agent-os/pull/11477#issuecomment-7091833286).

## Interface changes

The terminal job and round can contain `completion.publishedCiObservation`.
It carries the exact source head, observed check identities when readable,
historical watch status and current observer or recovery ownership. The
validated worker reply retains historic check names and run IDs. The public
comment reports the source effect and current successor. The existing proof,
review admission, closer and required-check gates still apply.

## Verification

The offline regression first reproduced a `stopped` closeout after independent
push proof. The new cases exercise legacy pending evidence, pending followed by
HTTP 401, subsequent green or red checks, permission denial, an unrelated
check head, missing source proof and a genuine operator-input blocker.
They assert the persisted source edge, public outcome and refusal to start a
second remediation on the completed final head.

- Scoped offline `npm test` for follow-up remediation and reconcile, final
  round completion and closer, closeout routing, PR comments and reviewer
  CI admission passed all 695 cases.
- `npm run lint` passed with zero errors and 147 existing warnings.
- `npm run typecheck:contracts`, the offline research-finding walkthrough,
  data-model catalog validation and `git diff --check` passed.

Runtime adoption and incident acceptance require an organic observation
on the normally deployed revision. Hosted exact-head required checks are
still required for merge.
