# LAC-2325 — Receipted closer lease recovery after a rekey

## Summary

The operator cancellation CLI used the legacy merge-agent dispatch store. For
agent-os PR #11424 it reported `cancelled=false lrq=none` while a carried AMA
lease still owned the current head. The AMA dispatch receipt lived at
`13e06867aeea349306d07b32cfc5c3948f81169b`, with the lease at
`27e51ae8ee54c12c40bb57e16378cf97c4ef340a`. A later read of the native lease
showed a successor LRQ at the same current head.

Cancellation and in-place repair now share a bounded release path for a
carried lease with exactly one matching `launch-terminal` receipt. The App SDK
checks the exact LRQ, original repo, PR and target head, and the complete retry
chain. Only terminal non-success evidence permits release. The PR intent lock
and exact lease CAS protect successors. The original dispatch, history and
retry accounting retain their recorded values.

## Interface changes

The operator cancellation receipt adds `result.closer` for AMA custody and the
CLI prints the closer disposition. A released terminal alias has
`cancelled=false` and `cleanupComplete=true`. Unsettled AMA custody returns a
retryable receipt without enqueuing PR-wide legacy label or worker cancellation.
In-place repair rechecks custody and continues through its ordinary reservation
gates after a proven release.

## Verification

The focused offline fixtures exercise native cancellation, repair admission,
multiple rekeys, terminal `no_work_done`, incomplete reads, identity mismatch,
live or parked retries, sticky success and a successor racing the proof.
The five scoped `node --test` suites passed all 100 cases.
`npm run lint` reported zero errors. `npm run typecheck:contracts` and
`bash demo/research-finding-walkthrough.sh` passed, with three byte-stable
transcript deliveries in the walkthrough.

Read-only incident verification used the public App SDK. Bootstrap succeeded.
Five-second reads of the original LRQ, its retry chain and the successor each
timed out. With a 45-second read budget, the original exact retry lookup
completed in 23.3 seconds and returned `failed/no_work_done` with the matching
original head and zero retry descendants. This establishes read latency for
the observed request. Source review and live readmission of the original PR
require separate evidence.
