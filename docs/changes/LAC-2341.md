# LAC-2341 · REVIEWBOUNCECUSTODY-01

## Summary

During watcher replacement, the original reviewer for agent-os #11492 remained
alive while its runtime accounting said `failed` and its claim said `pending`.
The operator later verified that the same session posted successfully at
16:44:08 UTC. The incident establishes a transient custody discrepancy.

`cli-direct` now records the actual spawn callback time for a detached reviewer.
A slow preflight previously aged the recorded timestamp before the process had
even started, which can deterministically break the process start-time check on
reattach. The runtime retains the record when a live group's identity is
inconclusive. Before any new admission, the watcher can restore an exact
failed/pending bounce claim to `reviewing` by matching its current head, session,
durable launch record, group leader, and launch arguments. The recovery retains
the original claim and counters. On exit, an exact GitHub review settles once
with its artifact and verdict. An absent reviewer with no post returns to the
existing bounded bounce retry path.

An unverified retained group or advanced PR head now holds admission only until
the bounded bounce deadline. Expiry returns control to the existing recovery
path without adopting or signaling that group. Bounce cleanup also checks the
reviewer's full launch identity before each signal. Malformed process output
reports an identity mismatch instead of a generic probe failure.

## Interface changes

The watcher restores verified reviewer custody automatically. Native
`review-cancel` uses its default `reviewing` status after adoption and verifies
the exact launch before recording cancellation intent and signalling.

## Verification

replacement races, a mismatched session or head, a reused group, genuine process
absence, expired unverified and moved-head holds, refusal to signal a mismatched

and an exact Comment-only review that already posted. Cancellation
fixtures cover a verified group and a claim replaced during the identity probe.
