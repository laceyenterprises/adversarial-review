# LAC-2295 Direct Codex remediation tool schema

## Summary

The direct worker for adversarial-review #1988, job
`laceyenterprises__adversarial-review-pr-1988-2026-11-21T08-49-02-295Z`,
received HTTP 400 `invalid_request_error` for `tools`. The provider reported
that function `web.run` is reserved for the model and must match its configured
schema. The combined log ends with `turn.failed` and records no source work.
The Code Mode startup warnings preceded the fatal event.

The retained isolated home pinned `model-catalog.direct-tools.json` for
`gpt-6.2-sol`. The selected entry had no `tool_mode` or `supports_search_tool`
after the direct-tools transform. The shared config still enabled Code Mode
and left web search at the CLI default. The entry retained
`use_responses_lite = true` and `web_search_tool_type = "text_and_image"`.
Codex fell back to the feature flag for Code Mode and independently serialized
the standalone `web.run` function for Responses Lite.

## Interface changes

Direct remediation retains the direct-tools catalog transform and explicitly
pins its feature settings in the isolated config and exec arguments. It selects
cached hosted search only for declared regular Responses with a supported
native search type. Lite and incomplete search declarations use disabled web
search. Unknown selected capability values or an unavailable catalog fail
before exec through the existing startup-contract failure path.

Native reviewer and discovery keep their native metadata and Code Mode policy.
The change applies to the local direct Codex launcher. The terminal direct
Codex schema diagnostic records a fixed, redacted reason without automatic
retry. No shared YAML keys, provider routing, or budget settings change.
