# LAC-2211 — settle reviewer outcomes before token accounting

## Summary

Read-only Nov 17 evidence distinguishes the two cases. Agent OS #11020 pass
62685 had its own Gemini GitHub artifact (5947219824) and was correctly completed
by the canonical reaper. Agent OS #11025 pass 62603 (Gemini, session
0316f829-a9cb-41a4-8ff2-c5d43a6cfb63, started 19:41:41.198Z) returned
`cli-resolution-transient` at 19:42:26.516Z. The watcher released delivery for an
infrastructure retry without charging recovery. Its log contains no subsequent
token-accounting/pass-completion receipt for that primary. A later route selected
corporate Codex: pass 62607, ledger attempt 2, session
b387cbbe-1b98-4fae-9744-7bf0119c1cf5, started 19:55:30.581Z. It posted review
5945594067 at 19:57:57Z on head
5786da575136489d6be0f6b5e199d185ee246429. Both passes retained logical round 1.
The Codex pass was recovered by the reaper and then enriched by late accounting;
its token-ledger lookup took 69,486ms. This was a later routed retry, not a
same-call Gemini quota fallback. No Gemini artifact can be inferred from it.

Sources: explicit read-only SQLite queries of the deployed `data/reviews.db` and
bounded matching lines from `~/Library/Logs/adversarial-watcher.log`. The logs
prove a missing settlement receipt, not the exact cause of the interruption.
The confirmed source gap is that delivery settlement precedes awaited token
lookup and pass completion. Interrupted or stalled accounting can therefore
leave a failed primary or posted pass running independently of delivery.

Persist the pass outcome and available runtime token evidence before delivery
handoff and token lookup. Malformed counters cannot block the outcome. Later
accounting enriches a terminal row in one transaction, retaining its end time,
final review evidence and outcome; another session cannot supply its tokens.
Reaper settlement rechecks the pass inside its transaction before touching
delivery or budgets, protecting concurrent outcome completion and replay.
Existing live/ambiguous process protections and logical attempt budgets remain
in force. Runtime databases, services and credentials were not changed.

## Interface changes

No schema, configuration, CI or status additions. `completeReviewerPass` accepts
an optional `expectedHeadSha` ownership fence. Terminal completion is monotonic;
verified first-pass/rereview delivery evidence preserves posted success. An
early real launch ID is recorded as pending attribution before accounting.
