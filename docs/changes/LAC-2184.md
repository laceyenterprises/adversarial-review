# LAC-2184 — ARFINALCHECK-01

## Summary

Final remediation previously delegated focused validation entirely to the worker.
That could miss the simulator bridge when finalization implementation hashes
changed, and the posted-review profiling fixture when migrations added sentinel
reads. The guarded publisher now selects those existing offline fixtures from
the full PR diff, including inputs changed before the final remediation commit.
It runs at most two fixtures in one 180-second invocation before publication.
Unrelated paths select neither suite. No CI job, hook, live action, simulation
outcome, baseline hash or runtime read-budget change is introduced.

## Investigation

`src/remediation-prompt-builder.mjs` asks for the smallest relevant targeted
validation and forbids a full local suite during remediation.
`test/run-tests.mjs` accepts exact test paths or basenames; it does not map
changed implementation files to dependent fixtures. The installed generic
`cwp_dispatch.worker_validation` diff selector emits pytest/shell commands,
leaving Node selection to explicit commands. Before this change,
`src/remediation-publication.mjs` enforced preservation and the remote lease
without executing any tests. Passing focused unit tests therefore supplied no
evidence about the simulator's implementation hash or migration sentinel
accounting. ARFINALCHECK-01 closes those two omissions inside this repository
without expanding the generic selector or running the full suite at publication.

## Interface changes

No new CLI flag. In this repository a selected fixture failure or timeout returns
`remediation-publication-check-failed`; a dirty selected workspace returns
`remediation-publication-dirty`. Both retain the previous remote head. The
existing final head check and exact remote-head lease still apply.
