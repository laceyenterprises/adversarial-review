# LAC-2329 Repair dispatch read preflight

## Summary

The native repair helper could return a successful reservation on a first
exhausted-PR submission without reading dispatch at all. HQ's repair caller
already passes the intended project and advances to admission when the
helper approves. The watcher later reads the resulting owner through the
review app's exact project/repository grant. A project accepted at dispatch
can therefore leave a finished, published repair unproven to the watcher.
The incident PR for the governance-event repair records a produced
attestation and green CI alongside a native `repair-owner-unproven` hold.
[Agent OS #11424](https://github.com/laceyenterprises/agent-os/pull/11424)

The helper now uses its registered review-app session and the existing
paired lookup to verify the exact project and repository before reserving.
The lookup uses a fresh probe key so it cannot interfere with the actual
dispatch key's ownership rules. The helper then rechecks the follow-up claim
and retries the reservation under the original ledger flock and predecessor
snapshot. The new read is
point-in-time evidence. Existing retry, publication and review predicates
still govern reconciliation.

The Agent OS PR-update and rescue submission paths use the same native
helper. The native follow-up claim path carries the existing job ticket and
parent PID through that boundary and rechecks them after the proof. Existing
legacy owner reads, including repository-only CWP conflict recovery, still
serve the epochs for which they were designed.

## Interface changes

A new exhausted epoch requires the existing ninth positional
`DISPATCH_PROJECT` argument and a qualified repository. The helper exits 75
with an actionable JSON reason for a missing project, a denied pair or
unproven visibility. HQ already surfaces the reason and short diagnostic.
Ordinary updates with budget and existing-key replay keep their established
paths. See the [operator runbook](../RUNBOOK-ama-closure.md#exhausted-cycles-and-new-builder-heads-exhaustedheadowner-01)
and [public dispatch read contract](../dispatch-absence-recovery.md).

## Caller compatibility and rollout

The producer change landed in Agent OS commit
[`c9da1e455` (#11417)](https://github.com/laceyenterprises/agent-os/commit/c9da1e455).
At that commit, `modules/worker-pool/lib/python/cwp_dispatch/dispatch.py:7099-7115`
has the single native `reserve_pr_repair` call: it takes `ctx.project_ref` or
`ctx.project`, falling back to `args.project` before reservation, and passes
`dispatch_project`. `cwp_dispatch/pr_repair.py:200-206` pads the native claim
slots and appends that project as argument nine.
The CWP conflict submission in `cwp_dispatch/auto_merge_daemon.py:3235-3247`
passes both `--project` and `--allow-conflicted-base` through this same dispatch
entry point. Rescue supplies `--project` in
`cwp_helm/merge_agent_rescue.py:3426-3459`, also reaching the shared call.
These paths all live beneath `modules/worker-pool/lib/python/`.

The inspected Agent OS checkout at `40c44feb8bb31f1408d1614ddd96768475790a42`
contains that commit. This is source evidence, not proof of a deployed caller.
The deployment owner must install #11417 or later before floating this
submodule, retain the resolved project through provisioning/enqueue, and
verify an organic exhausted/conflicting PR reservation uses that same project.
This ordered rollout qualifies the PR body's original “Post-merge activities:
None.” Producer deployment docs live in Agent OS and were not edited from this
submodule. No live build pack, grant or runtime state is changed here.

## Final comment-only remediation

New requests with no replay or pending epoch, below the cap and without a
project now refuse before closer alias or owner work. Existing custody paths
retain ordinary observation; the runbook explicitly describes terminal alias
settlement before a later successor refusal. The preflight now uses the
reader's load-aware default while retaining the intent lock and existing
post-read fences. HTTP 403 and the denial-code variants now produce the
scope-denied diagnostic; unsupported selectors remain unproven.
