# LAC-2206 — Recover posting-time approval reads through REST

## Summary

Reproduced the live-pack approval disagreement for
[agent-os#10931](https://github.com/laceyenterprises/agent-os/pull/10931),
head `64940132690815503602fc0fa490df576bc957af`, using read-only GitHub
evidence and the watcher log. Added an offline two-pack regression and a fresh
REST fallback after a failed GraphQL head/state read.

### Root cause and evidence

- The issue event records `VirtualPaul` applying `live-pack-edit-approved` at
  `2026-11-16T17:24:49Z`.
- Review `5924620316`, submitted at `17:41:54Z` against the named head, posted
  blockers for `gym-oss-extraction` and `paddock-web`.
- Watcher output for reviewer session
  `cdc81d08-3bfb-4160-9e33-e1ab80f32099` shows approval already present in
  dispatch arguments. Its delivery receipt records the verdict-mode read
  starting at `17:41:36.844Z` and taking 7,913 ms.
- That read failed with a GraphQL TCP connection timeout. The accompanying
  warning says `failed to resolve advisory-only label ... using enforce mode`.
  `fetchCurrentHeadVerdictMode` projected this failure to `labels: []` and
  `currentHeadSha: null`. The scope gate correctly used that fresh-read result,
  not the earlier dispatch/context labels, and generated both blockers.
- There was no REST fallback in the GraphQL branch of
  `fetchPullRequestHeadAndState`. This was acquisition failure, rather than
  approval arriving after review or a label-shape projection defect.
- Merge preflight follows a different acquisition path:
  `checkLivePackMerge` reads the REST PR (including labels), evaluates the same
  `evaluateLivePackCrossEdits` predicate, then rereads and compares inputs.
  The ticket's exact-head `waived=true` result is consistent with successful
  REST acquisition while posting-time GraphQL failed.

The PR has since advanced; the historical review and event establish the
incident timeline. No historical live-head check was rerun, live run state
changed, label mutated, review retriggered, or merge forced.

## Interface changes

No signature or store changes. The shared head/state helper now falls back to
the existing REST reader after GraphQL acquisition or pagination failure,
preserving telemetry and `withLabels` behavior. REST must freshly read the PR
and all label pages; failure propagates to the existing fail-closed consumer.
Dispatch/context labels remain ineligible to authorize a waiver.

The regression runs the production head/state reader, verdict-mode projection,
posting scope gates, and merge preflight with offline transports. It covers
approval added after stale empty context, approval removed after stale approved
context, and unreadable current labels for two simultaneously live packs.
