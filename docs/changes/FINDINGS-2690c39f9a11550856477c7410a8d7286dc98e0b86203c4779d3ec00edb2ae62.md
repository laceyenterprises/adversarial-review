# Live-pack review reliability

## Summary

Rechecked all five batch findings against origin/main at `35859e14`. Live-pack facts now appear within Summary only after a scan or ledger check, preserving the final optional advisory and omitting packs without plans. New-pack checks reconcile a moving base branch with the scanned commit, including its plan identity and tickets. Failed or malformed scans consult the ledger without granting exemptions from head-only tickets.

Base scans fetch at most 64 plans with four concurrent reads, shared across packs within one evaluation; larger listings fall back to the ledger. Ledger reads allow three load-aware eight-second attempts, with an overall budget of three attempt budgets plus 300ms of backoff. Existing collision, operator-waiver and scope-denial behavior remains enforced.

Final comment-only remediation stops scheduling additional base-plan reads after
any worker encounters a fetch or parse failure, while awaiting all in-flight
reads before the ledger fallback. The reported JSON `path` override is already
prevented by `parsePlanJson`, which returns only `planId` and `ticketIds`;
the snapshot regression now supplies a conflicting JSON `path` to pin that
boundary. No persistent store, lifecycle or smoke contract changes.

No exported API changes. The public facts block moves into Summary; scan failures can now produce conclusive ledger results.
