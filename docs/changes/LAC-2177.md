# LAC-2177 — HAMHISTORYTHROUGHPUT-02

## Summary

Agent OS #10268 and #10341 still hit the 90-second exact-head history context
after LAC-2174 / adversarial-review #1758 deployed. Their normal closure
lane/operator retains ownership and the next live attempt; this source PR takes
no custody and performs no target-PR or production-credential probes.

The prior repair parallelized directory reads but retained their request volume.
The reader now coalesces directory evidence into SHA-addressed recursive tree
snapshots. It first reads the roots, avoids recursive requests for flat roots,
and requires an explicit completeness marker, matching root entries, unique
valid paths, supported object modes/types and all directory ancestors. It rebuilds
every descendant Git tree object and verifies its SHA, catching omitted children
or changed modes even when the server claims completeness. Blob bytes, local
patches, deterministic path order, rename handling and reversal authorization use
the existing evidence path.

Explicitly truncated recursive responses fall back to the existing bounded,
equal-subtree-skipping walker. Missing markers, malformed snapshots, transport
errors and output overflow refuse evidence. Incomplete fallback trees still
refuse evidence. The global deadline includes both attempts. No new credential
source, token handling, config key, CI job, gate, lifecycle state or merge authority
is introduced. Live PR metadata and authorization/provenance remain live; existing
immutable caches retain their executor, credential and cancellation isolation.

This is the narrow live-PR unblock allowed by `src/ama/FREEZE.md`. The stable v2
scenario is `LAC-2177-history-request-fanout`: complete SHA-addressed evidence
must reduce directory fanout while validating descendant completeness, retaining
all protected patches and refusing incomplete evidence within the global budget.
The companion Agent OS requirements ledger remains outside this repository's
dispatch scope; this fragment records the scenario for its owner's capture.

None. `createHistoryReader` returns the same complete file evidence. The closure

## Offline measurements

The synthetic 2-commit / 53-path fixture carries no private history or production
latency measurements. The deployed
[LAC-2174 fixture](LAC-2174.md#offline-reproduction-and-measurements) required
1 compare, 108 tree and 106 blob requests = **215 API requests**, plus 53 local diffs. The new path
requires 1 compare + 4 tree + 106 blob requests = **111 API requests** (104 fewer,
48% reduction), with byte-identical complete evidence and 53 local diffs. A
truncated recursive response uses 217 API requests: the old walker plus two
bounded recursive attempts. Both full hammer snapshots share base-tree/blob
reads and still require complete primary and final evidence.

At an explicitly modeled six seconds per API wave, the deployed schedule would
need 96 seconds; the new snapshot schedule completes in **60 seconds** (one
compare wave, two tree waves, seven blob waves). A controlled scheduler executes
the production reader with real local diffs: the truncated fallback hits
`HISTORY_READ_TIMEOUT` at 90,000 virtual milliseconds; the recursive path returns
all 53 patches at 60,000. These are deterministic request-latency models, not a
claim of measured production latency or guaranteed live completion.
