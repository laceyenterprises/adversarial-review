# LAC-2196 — external merge leaves a dormant daemon waiter

## Summary

Lifecycle polling now reconciles persisted daemon reservations independently of
the open review mirror. A terminal live PR read must match repository, PR, full
head and base. Removal compares the complete pre-read waiter snapshot under the
existing per-base mutation lock. A concurrent refresh survives and is checked
again next poll, even after the review row becomes terminal. Ordinary waiters,
other daemon reservations, holder fences, FIFO and required checks are unchanged.

  `1402fdffb8d4d9bdd12ce3701eba60dbeecb78e3`, base `main`.
  The incident reports that this waiter still blocked #10789 at 07:11 with no
  holder, and that an operator removed only that waiter after terminal proof.

  `39808370458aa9984332693ada504424f4bc1277` at
  `2026-10-24T00:17:22Z`. Its reservation scopes surround

- The offline fixture calls the actual no-closer terminal callback, confirms
  `no-live-closer`, and proves the next closer cannot acquire despite an empty

Sibling inspection found the low-GitHub-budget shortcut also marks terminal
rows without candidate evaluation. The independent waiter scan covers those
rows on the next ordinary lifecycle poll; it does not bypass budget controls.
Lease acquisition and release-wake expiry/PID pruning retain their existing
rules. The fix neither changes merge eligibility nor infers terminal state from
age, PID liveness, or absence from open discovery.

Both required HCP scar searches were available and returned no matching records.
LAC-2087, the LAC-2098 RCA and the canonical lease runbook were inspected before
implementation. Their relevant lesson is that a long-lived service PID does not
prove a particular acquisition is active, and uncertain ownership must survive.
A subsequent lookup of the injected directive IDs timed out at HCP; their
supplied requirements remain in force. No merge before current-head adversarial
review, CI and normal merge authority is authorized by this work.

## Interface changes

`removeMergeLeaseWaiter` accepts optional `expectedWaiter` for a complete
snapshot comparison. `readDaemonMergeLeaseWaiters` returns valid exact daemon
identities from the durable queue files. `reconcileTerminalDaemonWaiters` owns
terminal verification and conditional removal; polling state now includes
`baseRefName`. No persistent shape, configuration, migration or CI check changes.
