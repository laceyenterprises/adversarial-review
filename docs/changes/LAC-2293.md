# LAC-2293 — Serialize automatic verdict claims with native merge custody

## Summary

On #1986, an automatic verdict-only reviewer claimed the same head after the
native merge holder passed its under-lease owner check. The final native gate
refused the operation. The watcher now uses the same per-base mutation lock as
native lease acquisition when it claims an exhausted-head system request.

## Interface changes

`native-merge-custody`, `merge-lease-mutation-busy` and
`merge-lease-base-unavailable`, plus `merge-lease-state-unavailable` for rename
recovery or unreadable lease data, are watcher claim deferrals. A deferred request
keeps its row, intent and attempt budget. A claim that commits first stays
visible to the existing native owner check. The fence grants no findings,
review, CI or source-preservation authority. It uses the existing lease schema.
An exact system marker also binds a legacy pending row after subject identity
backfill clears `revision_ref`. A conflicting revision prevents the match.

Final comment-only remediation adds an unlocked custody precheck before queueing,
dedup preflight and memory admission, with rechecks for queued candidates.
Custody deferrals suppress lane telemetry without retaining capacity wake
priority. The authoritative locked fence observes holder liveness outside the
mutation lock, then compares the complete lease before using that observation;
matching replacement holders defer. Missing base metadata uses the configured
default branch or `main`. Offline fixtures cover corrupt/unreadable lease state,
rename recovery, native release during the probe, replacement races and both
pool/hold-release transactional snapshot refunds. No store shape changes.
The existing PR-head CI failure was a stale watcher source projection.
Reviewed the claim guards and unchanged lifecycle transitions, then refreshed
that projection without changing the state graph or smoke commands.

### Recurrence interface changes

The existing native custody precheck and locked SQLite claim now recognize
exact-head repair-epoch requests. A confirmed lease deferral keeps the request
pending and spends no reviewer attempt. A review that commits first remains
visible to the native owner's ordinary under-lease check.

The epoch's attested final fix-all publisher owns admission through queue
settlement. The watcher then uses the existing exact-head completed job reader.
It restores an eligible automatic queue row only when the source review is
still the last delivered verdict, and rechecks a queued epoch claim before its
CAS. Regular human review and veto, exact-head merge proof, unresolved findings,
source preservation, CI/cost, and live or unknown owner checks remain merge
inputs. The repair reuses existing state and counters.

The HQ results were ordinary in-place publications. The `--no-rereview-request`
field is explicitly audit-only. It records preference even when the
publication is genuine. The prior final handoff and lease fences had no
authority over the unowned successor at claim time. Later exact-head source,
review and lease proof explains the eventual ordinary merges. The watcher
records and native cancellation artifacts identify the launches as automatic.

The watcher also treated a queued `system-exhausted-head-verdict` marker as
an exact-head recovery exemption, even when protected closure evidence had
become available. Only repair-epoch claims rechecked job completion near the
claim. A full automatic stale refresh took neither of those system verdict
paths and could claim during native merge arbitration.

The watcher now restores the last delivered source review for a queued
automatic verdict when a protected final job proves the same published head
and source review. The claim rechecks final completion inside the existing
transaction, alongside the priority receipt. An authenticated Hammer audit
can reclaim a queued automatic verdict at its exact head. A native publisher
still working or unable to confirm its mutation defers automatic execution.
A full automatic stale refresh with a delivered prior review uses the native
lease lock. Lease release makes an otherwise unproven head eligible to review
again. Root can retain custody before review admission through the native
publication or merge lease producer. The direct branch push records
publication, ancestry identifies history, and the budget tracks spent rounds.
