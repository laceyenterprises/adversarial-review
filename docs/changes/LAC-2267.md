# LAC-2267 — Hand off inconclusive canonical validation once

## Summary

The incident trace shows that the closer invoked standalone canonical
validation, which disabled CI coverage before reading any manifest. A separate
600-second shell alarm returned 142. The retained Telegram guard log reports
that process inspection produced no verdict despite 33 passing reload cases.
The closer followed generic retry guidance and started another battery on the
same head. This sequence does not reproduce the LAC-2240 registry parser bug.

Canonical deadlines and the explicit process-inspection no-verdict now stop
the battery with a typed UNKNOWN handoff. The closer ends the run after
preserving the original evidence and the existing cleanup disposition.

## Interface changes

One private `validation-deferred-<head>.json` per head in the run directory
records the reason, status, cleanup owner and local validation receipt path
when available. The validation and close entry points return 75 on repeat
for that head. The original controller and standalone cleanup evidence
remains authoritative for drain. A different head validates normally.

Standalone canonical validation can use the existing authenticated coverage
reader for a clean checkout at the live PR head. All checkout, head and base
manifest checks and exact command, job and step matching still apply.
Local-only and ambiguous checks run locally. Timeout and denied inspection
never earn validation success.

## Verification

Offline fixtures exercise registered absolute and per-check deadlines,
retained diagnostics, descendant drain, cancellation, single lease yield,
same-head reentry, a changed head, and clean versus dirty, stale, ambiguous
and invalid coverage evidence. The focused controller and coverage runs
passed 5 tests. The prompt and bounded-runner run passed 46 tests. An
overlapping controller run reached its fixture deadline and the isolated run
passed. ESLint reported zero errors. Contract types, the offline walkthrough,
the data-model catalog validator and Ruff passed.

After normal deployment, record the loaded revision and observe a natural
closer reach a canonical timeout or process-inspection no-verdict. Retain
its one exact-head handoff, diagnostics and owned cleanup evidence, and verify
that it starts no second same-head validation. A later eligible closer still
requires the usual exact-head evidence. Keep LAC-2267 open until that behavior
is observed after deployment.

CI closeout repairs two stale fixtures without changing the runtime contract.
The prompt contract now asserts the typed Appendix G2 stop/drain/no-retry
wording. The successful close fixture explicitly models both deferred checks,
including the second check after controller scratch retirement, and records
their calls rather than allowing an unknown helper. Hosted baseline exposed
both failures. The native two-file targeted run passed 90 cases with only the
obsolete prompt assertion failing; the corrected actual prompt test callback
then passed in isolation. No full-suite pass is claimed from that mixed run.
