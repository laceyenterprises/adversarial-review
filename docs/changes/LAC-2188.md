# LAC-2188 — FINALCAPHANDOFF-01

## Summary

The consecutive nonblocking claim cap now produces an explicit actionable
terminal result. The atomic stopped-job move records `finalCapResult` and the
stop reason names operator canonical rescue and says no successor was dispatched.
Claim/consume callers receive the same result. No automatic successor is added.

Incident evidence supplied with the ticket: Agent OS #10422 at
`33da88e271d3ec6216dc5c13fa0d7cf4a88253ea` received actionable comment-only
findings at 04:30:59 UTC. Its pending job stopped at 04:31:52.670 UTC on
the 1/1 nonblocking cap, before worker admission, without a closure handoff.
Live ownership probes found no successor; canonical rescue at 04:36:56 UTC
selected remediation requiring a hammer. The head was conflicting with green
hosted CI. No live records were changed or independently reconstructed here.

Source trace:

- `claimNextFollowUpJob` claims the queue file, then refuses the spent
  consecutive nonblocking budget before allocating a worker round.
- Previously that branch only wrote `max-rounds-reached`; the consume-time
  hammer wake handles settled-clean stops, which actionable findings are not.
- The canonical selector's R10 conflict route precedes R14 findings. Green CI
  does not remove the conflict. The final fix-all orchestration explicitly
  excludes R10; otherwise exhausted exact-head comment-only findings may use
  that existing deduplicated handoff before hammer fallback.
- CLOSERPARKOWNER-01 lets later overdue discovery continue to posted-review
  closure. Its source presence does not prove the incident's loaded revision,
  nor does it supply a missing pre-claim closure receipt.

The permitted explicit-terminal alternative avoids another executor path.
Strict shared-parser count/state accounting, stop-time job revision, cap and
lease precedence remain intact. Unknown findings stay unknown. A repeated
poll cannot consume the removed pending file twice. Settled comment-only
reviews retain their existing clean closure wake without another re-review.

The rescue operator owns PR #10422, live records, deployment/loading proof and
any subsequent rescue decision.
