# LAC-2357 — Preserve committed repair replies

## Summary

A cap notification runs after an above-cap operator supersession commits. A
throw from that notification used to suppress the reservation reply. Return
the original outcome with a fixed warning and preserve the alert latch's retry
behavior. The cap path logs a fixed warning with a bounded error class to
stderr, and the runbook assigns notification follow-through to Agent OS.

Both final-fix and retained repair recovery now reject a reservation with a
recorded publication launch before live PR identity reads or dispatch preparation,
matching the existing locked replay predicate.

## Interface

The companion advertises `retained-repair-replay-v1`. Operator rescue can read
back its one matching, unbound epoch after a fresh paired app read, two live PR
identity checks, and a compare under the existing intent and ledger locks.
The reply distinguishes a bootstrap failure, scope denial and unproven absence
without forwarding SDK error text. Agent OS owns HQ authorization and canonical
enqueue checks. Deploy this producer before enabling the corresponding Agent OS
consumer.

Retained conflict replay accepts reservations made before a review row exists
and still verifies the live PR twice. Bootstrap failures include the dispatch
scope during closer lease inspection. Recovery callers can also supply the
negotiated protocol as the final argument. A mismatch with the key family
refuses the request before opening the review database.

## Verification

The cap fixture failed on the baseline when the notification threw. The updated
`test/repairdispatchread-01.test.mjs` verifies that the replacement is durable
before the throw, the reply carries the same epoch, and the latch retries and
deduplicates. The suite also exercises exact scope, missing bootstrap, denied
grant, filtered absence, live ownership, a conflicting project and a moved PR
head using offline fixtures. All 83 tests passed.

The remediation fixtures reproduced both failures before the fix.
`node --test test/repairdispatchread-01.test.mjs` passed all 85 tests after
the fix, including checks that a closed live PR still refuses replay and a
successful replay leaves the ledger file in place.

Final comment-only remediation added two publication-launch preflight fixtures.
The final-fix case reproduced the unnecessary live PR read and dispatch
preparation before the fix; retained recovery already rejected early.
`node --test test/repairdispatchread-01.test.mjs` now passes all 87 tests,
including zero-network rejection and unchanged ledger bytes for both protocols.
`npm run lint` passed with zero errors (147 existing warnings),
`npm run typecheck:contracts` passed, and
`bash demo/research-finding-walkthrough.sh` passed its byte-equivalence check.
The full local test suite was deferred to PR-head CI as required for this round.
