# LAC-2264 · Cold live-pack merge preflight

## Summary

The installed `bin/live-pack-check.mjs` entered the shared live-pack evaluator
before preparing the review app's read context. The saved cold run for
`agent-os#11150` refused because worker observations were disabled. With the
existing app session prepared in the same process, the native evaluator cleared
the recorded heads of `agent-os#11150` and `agent-os#11196` with `waived: false`.

The CLI now prepares the declared `adversarial-review` app read context once
before invoking the evaluator. The entry-point audit found that
`repair-in-place` and the GSR lease release already prepare their context. The
hammer remediation guard has a tested conservative policy for inconclusive
liveness. The observed cold merge-preflight failure was specific to
`live-pack-check.mjs`.

## Interface changes

`node bin/live-pack-check.mjs OWNER/REPO PR HEAD` returns exit 1 with JSON
containing `ok: false`, `reason: "dispatch-context-unavailable"`, and a fixed
redacted `detail` when the existing app session cannot be prepared. It returns
before reading the PR or plan. The existing exact-head and approval checks
run after successful preparation. See the [closure runbook](../RUNBOOK-ama-closure.md#operator-label-closure-holds-labelgate-01).
