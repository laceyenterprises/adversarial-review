# LAC-2182 — ARNODE22BUDGET-01

## Summary

Reduce repeated Node startup work in the offline hammer shell fixture.
Partition the same 76 scenarios round-robin across three test entrypoints,
backed by one shared suite, and schedule those files first in the existing
eight-worker pool. Model a delayed wakeup in the permanently pending fixture
to exercise the last-second deadline boundary without 30 identical samples.
All original scenarios and assertions remain enabled.

## Interface changes

None to production. No changes to required checks, CI jobs, runner deadlines,
production retry allowances, sandbox isolation, or process-group cleanup.
Selecting only `hammer-self-rebase.test.mjs` now runs the first shard;
select all three entrypoints for the complete subset, as documented in
`CONTRIBUTING.md`. Default `npm test` still discovers every case.

The hammer test, its CLI fixture, and the runner are byte-identical between
the incident head, the launch checkout `9fd950852`, and unchanged
`origin/main` at `082ce3ba7`. The eager-import design and alphabetical queue
placement therefore also exist on main; this comparison alone does not
isolate differences elsewhere in the production dependency graph.

Local profiling uses macOS Node `22.22.3`, rebuilt local native dependencies,
the real sandboxed runner, and synthetic Git/GitHub state. It cannot
reproduce the hosted Linux machine or prove a Node engine regression.
Five bounded subprocess probes of the unchanged fake
`gh pr view --json title` take 206, 202, 225, 205, and 211 ms.
Independent three-sample import probes take 107–115 ms for
`checks-summary`, 223–238 ms for `merge-eligibility`, and 165–195 ms
for `legacy-lane-write`. These are process wall times, not additive
module self times.

An isolated temporary archive of unchanged `origin/main` at `082ce3ba7`,
using the same local dependencies and five identical bounded title reads,
takes 242, 243, 203, 217, and 212 ms. The optimized fixture takes
62, 73, 65, 67, and 85 ms (median 67 ms versus main's 217 ms).
The archive and fixture state were removed after the measurement.
This is a runtime comparison of that fixture operation; a full unchanged-main
suite was not run.

Every fake GitHub invocation previously loaded all of those dependency
graphs, including the native queue store, even when it only needed a JSON
field. Mode-local imports remove that repeated work while still invoking
the real classifier, eligibility predicate, attestation publisher, range
validator and lane writer in the modes that exercise them.

An intermediate full local run with lazy imports and one prioritized serial
file still reached the 900-second ceiling. It reported 65 passing records
from that file and a 45-second subprocess SIGTERM in `prepredicate-timeout`;
later files' output was buffered, so that is not a count of all executed
tests. The isolated 77-test run passed in 535.504 seconds. This reproduces
the serial integration file's sensitivity to full-pool contention locally,
without establishing the hosted machine's precise contention profile.

The final scheduling change partitions registration deterministically across
three entrypoints, retaining a single fixture/assertion implementation in
`test/helpers/hammer-self-rebase-suite.mjs`. All three start in the first
pool of eight workers. No worker, CI job, or deadline is added.
The permanently pending fixture additionally models a delayed wakeup at 899s
and checks the final one-second sleep, refusal at 900s, absence of a merge
or initial predicate, and released lease. Intermediate identical pending
samples are removed; the absolute deadline and production polling code remain.

The measured redundant startup cost and hosted long tail are reproduced
observations. Their contribution to the hosted failure is an inference;
only hosted CI on the new head can establish its Linux budget margin.

## Verification

All validation runs use
`PYTHONPATH=<worker-pool>/lib/python python3 -m cwp_dispatch.worker_validation
--repo-root . --timeout-seconds <budget> --command <argv>`.
The wrapper scales nominal budgets with host load; the actual test runner
retains its fixed 900-second deadline and process-group cleanup.

- Unchanged launch checkout: Node 22 `test/run-tests.mjs
  hammer-self-rebase.test.mjs`: 76/76 pass, 753.601 seconds.
- New native-loading regression: fails before the import fix with
  `unexpected native store initialization` through `fs-ext`.
- Intermediate lazy-import Node 22 `test/run-tests.mjs hammer-self-rebase.test.mjs
  hammer-self-rebase-startup.test.mjs`: 77/77 pass, 535.504 seconds.
  This includes all 76 original cases plus the regression: an observed
  218.097-second (28.9%) reduction from the launch baseline. Host load
  was not controlled, so these are observations, not a timing guarantee.
- Node 22 runner isolation/cleanup tests:
  `test/run-tests.mjs runner-sandbox.test.mjs hq-root-runner.test.mjs`:
  15/15 pass, 12.095 seconds.
- Final Node 22 subset: all three self-rebase entrypoints,
  `hammer-self-rebase-startup.test.mjs`, `runner-sandbox.test.mjs`, and
  `hq-root-runner.test.mjs`: 92/92 pass in 183.595 seconds.
  Comparing successful TAP names to the unchanged launch run confirms
  every original scenario passed exactly once (76/76, no duplicates).
  A whitespace-normalized diff of the moved case bodies against the launch
  source has no removed/changed lines, only six added lines of deadline assertions.
  This wall-time comparison includes the intentional scheduling change;
  the pool remains capped at eight workers.
- `npm run lint`, ESLint on the changed/new test modules,
  `npm run typecheck:contracts`, and
  `bash demo/research-finding-walkthrough.sh`: pass.
- Final full Node 22 `npm test`: reached the unchanged 900-second ceiling
  after 15,815 top-level passing TAP records. All 76 original hammer cases
  passed exactly once in this full run as well. One assertion failed in the
  untouched `test/ham-bounded-git-sync.test.mjs:152`:
  `bounded submodule expiry sends TERM and waits for lock cleanup`
  found its fixture lock still present. The last reported cases were later
  certified-lease-park tests. This is not a green full-suite result; the
  separate lock-cleanup failure was not investigated or waived here.

The final change removes the reproduced serial hammer tail locally, but the
entire local Node 22 suite still exceeds its budget. Neither a full unchanged-main
run nor hosted CI on this new head is available in these measurements.
Required hosted checks must establish Linux budget compliance before merge.
