## Interface changes

The hammer records writer intent before the click and reads GitHub after the
writer returns. `merge-writer-deferred` retains the head, base and writer
diagnostics in the AMA audit and assigns one closure recovery handoff per head.
An open PR observation and an unknown write remain distinct. A confirmed
GitHub merge after an ambiguous write settles terminal state without own-merge
credit. A later attempt needs changed live inputs and all ordinary closure
gates. The watcher and daemon read the live branch ref for base movement
because the PR payload can contain a historical base SHA.

The hosted CI follow-up corrects the capture-base and receipt shell fixtures
and updates the lease fixtures to supply the writer's diagnostic fields. A failed
optional receipt preserves the merged phase and the successful audit after
writer intent. A proven preflight refusal settles the intent under the
existing refusal classification. An ambiguous transport result still
depends on live readback. The closer keeps the existing corrupt
park-audit refusal and warning.

The rescue CI follow-up pins stable conflicts and permission rejections to the
new permanent refusal (exit 1, released lease, no retry refund). A separately
proved moving base still returns 21 and its existing retryable release. The
disposable smoke fixture supplies an `info` sink and passes its quiet logger to
every launch scan, keeping delayed diagnostics out of its final evidence line.
Missing-review fixtures also bind their own HQ root so the new writer-audit
read stays inside the disposable canary instead of consulting a host default.
No production rejection, lease, smoke assertion or timeout is relaxed.

A second hosted failure exposed a test-clock race: compressing the first wakeup
straight to one second before the deadline started a real Node gate under a
one-second alarm. A controlled 1.25-second gate delay reproduced both affected
cases in all three pre-fix runs (six failures). The fixture now starts its final
read 17 virtual seconds before the same deadline and models 16 seconds of read
latency. Five consecutive paired runs then passed (ten cases), preserving the
original 900-second deadline, non-default 47-second cadence, final one-second
sleep, refusal outcome, and released lease. This changes fixture time only.

## Final review remediation

The daemon checks the local writer audit before acquiring the lease and
again under the lease. A hold that appears during acquisition keeps the
lease release charge. Later held passes skip the gate and audit and pace
remote identity probes. The live branch lookup can fall back to GitHub's
branch endpoint within the same read budget.

A proof timeout or unclassified preflight refusal with verified
non-invocation settles the intent and allows ordinary bounded redrive
with the launch and lease charges intact. A
transient confirmation failure after an already-merged observation uses
the existing accepted-confirmation deferral. GraphQL integration and
write or admin access refusals can produce a permanent refusal, including
after a definitive credential rejection and refresh. A later refusal
retains reconciliation custody if an earlier click remains ambiguous.
Writer diagnostics preserve up to 16 KiB of redacted output per stream.

The in-run retry remains bounded by the existing deadline and lease. It
recovers transient transport errors and stale credentials after fresh
head, base, gate and review checks. Retiring the legacy repair fences or
migrating the writer to queue authority would change recovery ownership
outside this remediation. The operator reconciliation command remains in
the closure runbook.
