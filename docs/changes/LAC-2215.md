# LAC-2215 — Ground global file claims at the reviewed head

## Summary

Bounded reviews now receive positive file-path evidence from the requested
immutable commit, with changed paths prioritized within a 16 KiB path budget.
Every prompt includes explicit rules against inferring global absence from a
chunk, rename, inventory omission, or stale scope prose, and against importing
another repository's generated-file policy into an app validator.

Final comment-only remediation stops path serialization once fewer than three
bytes remain, since even an empty JSON string and newline cannot fit. Longer
paths are still skipped when a later shorter path could fit; partial coverage
continues to forbid treating omissions as absence.

The classifier, review thresholds, finding aggregation, and merge authority are
unchanged. File presence does not clear independently actionable defects.
No changes were made to lacey-web #37, runtime state, services, or credentials.

## Interface changes

`loadReviewerFileInventory` fetches a recursive Git tree by full commit SHA,
emits bounded positive evidence, and labels partial/unavailable coverage.
Only complete inventories support literal membership checks; capped,
API-truncated, or submodule-containing trees cannot establish absence by
omission. A default-checkout snapshot cannot prove PR-head absence without a
matching revision.
Budget deferrals propagate; ordinary read failures retain review with targeted
verification required for absence claims. `buildReviewerExtraContext` accepts
`fileInventoryContext`, including slim and public-hygiene context paths, and
`reviewedHeadSha` to pin linked-document reads and head-scoped context when live
PR metadata has advanced.
Shared prompt assembly always carries grounding guidance, even when chunk
budget fallback omits optional split-hunk context.

The app validator at that commit reads the November 18 migration and uses

Its `--write` branch writes the catalog. Removing that checked-in catalog
would conflict with this validator; Agent OS regeneration conventions do not
establish the app's contract.

Before this change, `buildReviewerExtraContext` appended author-controlled PR
intent prose to each pass without any commit-tree inventory.
`reviewAgyOversizedInChunks` repeated that context alongside each partial diff.
The chunk legend covered removed lines and split-hunk post-images only.
Antigravity's prompt discouraged repository listing. The workspace snapshot
was prepared from the default checkout without requiring its SHA to match the
requested review head; an allowed local lookup could therefore also miss a
new PR file. The patch retains that workspace boundary and explicitly prevents
using its omissions as PR-head evidence. Thus a chunk could see
obsolete scope paths as its only global path context, with no instruction
requiring exact-head verification before an absence assertion. Existing
post-review quote grounding does not establish global file absence or app
validator policy.

This deterministic omission is reproduced offline, including eight final-stage
chunks. The historical model's complete input trace was not recovered, and the
tests do not claim deterministic reproduction of Gemini's reasoning. Incident
tree entries and validator excerpts are preserved in
`test/fixtures/reviewer-file-inventory/lacey-web-37.json`; the chunk diff is a
synthetic regression fixture, not the historical app diff.
