# LAC-2240: Current CI registry coverage

## Summary

The closer coverage reader required the retired path-glob format. Agent OS now
publishes ID-keyed checks maps, so parsing failed before any CI evidence read
and all selected checks ran locally again. Native closeouts for #11214 recorded
manifest-read-failed and repeated 601/604-second inconclusive validation. This
compatibility defect is proven; it does not explain every timeout or actual
failing test in the fleet.

The reader now recognizes current mirror contributions and keeps legacy support.
Current CI mappings require a unique successful workflow step in the exact
successful job, in addition to unchanged checkout/head/base manifests and all
existing identity checks. Local/advisory or unknown mappings stay local. The
existing read deadline, quota reserve, validation budget and required checks are
unchanged; no CI check or workflow step is added.

Final comment-only remediation isolates malformed current entries instead of
discarding unrelated mappings, tolerates additional lane names and defaults
missing path scope to an empty list. Job-detail budget deferral stops further
reads and labels unread evidence `ci-budget-deferred`; manifests that failed
head/base verification no longer consume job-detail reads. The runbook now
explicitly documents that pinned declarations still trust PR-head workflows.
No workflow guard or CI change is introduced.

## Interface changes

Current step-level `ci-covered` receipts add optional string `jobId` and `step`
beside the existing `name` and `runId`. Legacy receipts remain unchanged.
The controller data-model doc and both catalogs describe the additive fields.
Lifecycle states, merge authority and existing smoke promises are unchanged.
