## Source and loaded generation

The incident identifies loaded adversarial-review generation
`6dbb923a0aaea62581002d68ba6d01ed81d67743`. It is an ancestor of merged
[AR #1964](https://github.com/laceyenterprises/adversarial-review/pull/1964)
(`141f7f70bcab3551d2a1d72781ea2098601df7ed`). The older implementation uses
an unscoped key and can classify overdue canonical emptiness as terminal.
The reviewed implementation binds positive evidence to the original key,
qualified repository and base-head identity, rejects explicit contradictions
and checks the complete retry chain. The watcher requires a verified
produced-head attestation by that launch or its retry before binding a moved
head. An invalid or unreadable proof retains custody. Canonical emptiness
also retains custody, with operator escalation after repeated observations
and the ten-minute threshold. The daemon liveness reader reported running
watcher and follow-up PIDs with unresolved build SHAs during this RCA.
[Agent OS #11303](https://github.com/laceyenterprises/agent-os/pull/11303)
records the earlier pin and was closed in favor of native main-catchup
submodule float.

`{idempotency_key, project_ref, repo}`. The producer requires the explicit
project/repository pair in the review app's `dispatch_reads` grant. It checks
canonical matches before granting selector-bound absence and only returns
authorized positive rows. A legacy epoch sends `{idempotency_key}`; replay
cannot add scope. The following caller snapshot is historical and superseded

At the time of this handoff, the Agent OS main source called `reserve_pr_repair`

on the caller owner freezing the same original project and repository used

and [repair and closure rules](../RUNBOOK-ama-closure.md#exhausted-cycles-and-new-builder-heads-exhaustedheadowner-01).
