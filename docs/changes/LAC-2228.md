# LAC-2228 — Native follow-up repair reservation

## Summary

The saved job `laceyenterprises__agent-os-pr-11159-2026-11-19T21-25-01-300Z`
at `0ff19e32f0bae60a8c3ddf6ddfac0c3c3d476280` records `hq dispatch --ticket` with
that job ID, followed by `repair reservation refused: remediation-owned`. Its
terminal record says `never-spawned`, carries no LRQ, and names launcher PID
16511, which was absent when checked. The refusal occurred before worker
provisioning or launch.

The native dispatch uses the follow-up job ID as its explicit ticket. Agent OS
preserves the ticket separately from PR metadata, accepts the matching claim in
its local preflight, then drops that identity when invoking the repair helper.
The helper saw the same job in `in-progress` as a competing remediation owner.
An offline run through the real job creator, claim and native argument builder,
the installed Python `reserve_pr_repair`, and the Node CLI reproduced both
decisions in order with a synthetic PR and head.

## Interface changes

The private reservation helper accepts an optional explicit dispatch ticket
and the native dispatch caller's actual parent PID. It verifies these against
the sole active HQ pre-spawn claim for that exact PR and head while holding the
closer intent lock. The job stays in the queue and the existing repair ledger
serializes the reservation. Unreadable claim evidence returns
`remediation-ownership-unknown`. A dispatch-key replay against a different
base head returns `repair-head-mismatch`. The repair-cap, closer and existing
epoch ownership checks still run. The handoff reuses the existing store fields.

1. Merge and deploy the reviewed adversarial-review source through the normal
   submodule float. The legacy Agent OS caller still uses the six-argument
   interface and retains its current refusal when a follow-up claim exists.
2. Apply the [Agent OS companion patch](LAC-2228-agent-os.patch) in a separate
   Agent OS source PR and deploy it through the normal process. The older
   helper ignores the appended arguments and retains its current refusal, so
   either mixed version keeps the fence. Both versions must be loaded for the
   handoff to work. The patch targets the installed caller as observed at
   Agent OS `a55480ab9`.
3. On a naturally occurring eligible native follow-up, confirm the active
   claim remains in the queue while one reservation leads to one launch on
   the original PR. Confirm the reservation's base head matches dispatch and
   the changed builder head goes through the existing exact-head re-review.
   Track merge, deployment, and live recovery independently of PR publication.

LAC-2226 owns token timeouts, terminal retries and stale unknown repair-epoch
recovery. This change uses the existing ownership observations for those cases.
