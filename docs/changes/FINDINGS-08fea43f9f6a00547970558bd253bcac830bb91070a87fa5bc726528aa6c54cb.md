# Hammer review evidence across completed remediation

## Summary

Ordinary remediation rounds that request another review can keep the prior
findings visible through an authenticated mixed chain. An App push after one of
those rounds leaves the requested exact-head review outstanding. The closer's
range validation, stale-verdict carry-forward and provenance-based head-match
waiver now use the same eligible round edges. A completed round without a
re-review request can still bridge those proofs.
Final Comment-only remediation preserves cancellation and timeout errors,
retains authorship diagnostics on capped supplied rollups, and exercises
comment-only final and pending-CI round shapes. The runtime operator owns
completed-history archival; no automatic retention bound is claimed.

## Interface changes

`mixed-remediation-provenance` admits findings and can include `patchProofError`
if the independent patch-equivalence read fails. Stale-verdict proof reports
`completed-remediation-rereview-required` when it needs an excluded round edge
and `hammer-app-attestation-comment-limit` when comment evidence is capped.

Completed-job enumeration has no directory-entry ceiling. The matching-file
and distinct-edge budgets remain 256 each. Warnings recur once per minute per
repository, PR and limit kind while tracked in the bounded process cache.
Abort and timeout errors propagate from review-currency reads rather than
becoming `patchProofError`. Real rollup arrays retain
`currentHeadHammerAttested` at the comment cap; capped-reader sentinels leave
it unknown. Comment-limit proofs intentionally retain retry-series exhaustion.
Persistent record shapes, lifecycle states and smoke promises are unchanged.
