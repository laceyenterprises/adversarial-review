# LAC-2177 — HAMHISTORYTHROUGHPUT-02

## Summary

Agent OS #10268 and #10341 still hit the 90-second exact-head history context
after LAC-2174 / adversarial-review #1758 deployed. Their normal closure
lane/operator retains ownership and the next live attempt; this source PR takes
no custody and performs no target-PR or production-credential probes.

The prior repair parallelized directory reads but retained their request volume.
The reader now coalesces directory evidence into SHA-addressed recursive tree
snapshots. It first reads the roots, avoids recursive requests for flat roots,
and requires an explicit completeness marker, matching root entries, unique
valid paths, supported object modes/types and all directory ancestors. It rebuilds
every descendant Git tree object and verifies its SHA, catching omitted children
or changed modes even when the server claims completeness. Blob bytes, local
patches, deterministic path order, rename handling and reversal authorization use
the existing evidence path.

Explicitly truncated recursive responses, transient transport failures and output
overflow fall back to the existing bounded, equal-subtree-skipping walker.
Syntactically valid legacy modes such as `100664` also select the walker after
structural validation. Missing markers, malformed snapshots, tree-SHA mismatches,
permanent API refusals and malformed JSON refuse evidence. Incomplete fallback
trees still refuse evidence. The global deadline includes both attempts; expiry
and abort never select fallback. No new credential
source, token handling, config key, CI job, gate, lifecycle state or merge authority
is introduced. Live PR metadata and authorization/provenance remain live; existing
immutable caches retain their executor, credential and cancellation isolation.

This is the narrow live-PR unblock allowed by `src/ama/FREEZE.md`. The stable v2
scenario is `LAC-2177-history-request-fanout`: complete SHA-addressed evidence
must reduce directory fanout while validating descendant completeness, retaining
all protected patches and refusing incomplete evidence within the global budget.
The companion Agent OS requirements ledger remains outside this repository's
dispatch scope. The outstanding obligation is tracked in
[follow-up issue #1775](https://github.com/laceyenterprises/adversarial-review/issues/1775):
the Agent OS merge-lane-rebuild owner must add
`LAC-2177-history-request-fanout` to the
[requirements ledger](https://github.com/laceyenterprises/agent-os/blob/main/projects/merge-lane-rebuild/requirements.json)
and reflect its disposition in `REQUIREMENTS.md`, including recursive transport
fallback and legacy-mode scenarios. No matching row was found in the local
Agent OS ledger during final remediation. This records an outstanding FREEZE
obligation, not completed cross-repository work.

## Offline measurements

The synthetic 2-commit / 53-path fixture carries no private history or production
latency measurements. The deployed
[LAC-2174 fixture](LAC-2174.md#offline-reproduction-and-measurements) required
1 compare, 108 tree and 106 blob requests = **215 API requests**, plus 53 local diffs. The new path
requires 1 compare + 4 tree + 106 blob requests = **111 API requests** (104 fewer,
48% reduction), with byte-identical complete evidence and 53 local diffs. A
truncated recursive response uses 217 API requests: the old walker plus two
bounded recursive attempts. Both full hammer snapshots share base-tree/blob
reads and still require complete primary and final evidence.

At an explicitly modeled six seconds per API wave, the deployed schedule would
need 96 seconds; the new snapshot schedule completes in **60 seconds** (one
compare wave, two tree waves, seven blob waves). A controlled scheduler executes
the production reader with real local diffs: the truncated fallback hits
`HISTORY_READ_TIMEOUT` at 90,000 virtual milliseconds; the recursive path returns
all 53 patches at 60,000. These are deterministic request-latency models, not a
claim of measured production latency or guaranteed live completion.

## Reopened recurrence

### Summary

Agent OS #11177 at `33d8e8981985ddc2bd39b4d6cd275ea1f5c76430`
returned a transient history timeout from the native exact-head collector and
same-process predicate on the first read and one bounded resume. The canonical
owner's checkpoints show that the primary and projected final patches had
been collected and the reader reached the historical scan for an original
reversal pinned by a superseding review. Three successive review ranges
checkpointed 403, 514 and 554 file comparisons. The first of those range pages
and the last file checkpoint were about 45 seconds apart. The last checkpoint
landed at the deadline. The aggregate patches were unused in the candidate
search, which only matches commit messages or trailers before fetching the
original commit. The timeout receipts establish a read failure for the named
head. The live source and its next eligible verification remain root-owned.

The narrow fix uses the existing paginated `commitHistory` for candidate
discovery. Prior durable compare pages remain reusable. A candidate still
requires an independent exact-SHA commit patch, provenance, required parent
and reviewed snapshots, and finding coverage. Invalid pagination remains a
history-read failure. See the [closure runbook](../RUNBOOK-ama-closure.md).

The fixture extends the `LAC-2177-history-request-fanout` requirements
scenario with superseding reviews and an interrupted commit page. The Agent
OS ledger update remains with its owner under [#1775](https://github.com/laceyenterprises/adversarial-review/issues/1775).

### Verification

The offline regression uses a fixture transport and real local Git diffs.
With the pre-fix source, the first attempt exhausted 90,000 modeled
milliseconds on page two, and the resume timed out during unused blob reads
after 20 requests and 92,000 modeled milliseconds. With the fix, the
first attempt reached the same page-two boundary after 26 requests. The
resume reused page one and needed 6 requests and 600 modeled milliseconds
to return a verified reversal via the later review. The additive request clock
provides deterministic evidence for this fixture. It does not estimate live
wall-clock time. Negative cases cover absent candidates, partial pagination,
absent or partial commit reads, mismatched commit identity, and mismatched
patches. Missing refusal diagnostics grant no preservation authority.
