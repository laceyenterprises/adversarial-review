## Cancellation evidence and limits

The first unauthenticated cancellation attempt in `9043-stalled-cancel.log`
was refused. The authenticated HQ action subsequently produced canonical
`canceled` at 20:26:39Z, with no worker lease (`9043-holder-status.json`).
`9043-cancellation-confirmed.json` verifies PIDs 60630, 16889, 16896 and 16904
were all gone by 20:30:11.045570Z, without direct rescuer signals. This bounds
the final observation to about 212 seconds after canonical terminality; it is
not the exact exit time or the configured cancellation grace. The merge queue
advanced. There is no evidence of a permanent cleanup leak.

The worker supervisor escalates its recorded process group across ticks and
uses a configured grace (`supervisor_recovery._apply_requested_actions` in
agent-os). The policy's compiled default is 30 seconds, overridable by
`timeoutGraceSeconds`; the receipts do not retain the incident's loaded policy
or exact signal/escalation times. The old runner itself created another process group using
`setpgid(0,0)` but forwarded only its own absolute-timeout alarm, with no
TERM/INT/HUP handler. This independently reproducible local forwarding defect
can leave validation outside the native parent's cancellation group until
canonical descendant cleanup. The receipts alone cannot assign every second
of the observed interval to that defect versus supervisor/reaper cadence.

The replacement supervisor handles TERM/INT/HUP with group TERM and keeps
five-second KILL escalation alive after the validation leader exits. Synthetic regression groups
include a TERM-ignoring descendant. SIGKILL of the supervisor and descendants
deliberately leaving its group still require canonical worker cleanup.
An enclosing Perl alarm is handled as SIGALRM: it initiates the same cleanup
and returns timeout status 124 instead of abandoning the validation family.
If group signaling is denied, the supervisor also tries its still-live direct
child. Cleanup that cannot be confirmed returns 125, with `cleanup=unconfirmed`,
after the five-second escalation and one-second pipe-drain allowance. It never
turns a timeout into acceptance or an indefinite lease hold; canonical cleanup
must reconcile survivors. A synthetic permission-denial fixture covers this
without signaling any real process.
The lease helper retains its private scratch on reserved cleanup-failure status
125 or an unexpected supervisor exception, so canonical cleanup can reconcile
survivors without unlinking diagnostic ledger files from under them.

## Source acceptance

`hammer-validate.mjs` applies an unscaled 120-second idle bound and a separate
load-scaled absolute bound, nominally 360 seconds. `--nominal-timeout 1..3600`
selects a project's nominal budget without changing idle or the existing helper's
absolute ceiling. Its pytest plugin emits real
plugin/session/collection/test/report events through the original stderr,
including setup, call and teardown results; it sends no periodic heartbeat.
The generic runner exposes `--idle-timeout`; without it only the absolute bound
applies. The lease helper always fixes the idle bound at 120 seconds. The runner
retains only a bounded tail and reports elapsed time,
idle time, child bytes, outcome and status. Neither timeout nor test failure
authorizes a validated-head audit. The lease-owning script must exit on nonzero.

Deterministic offline regressions in `test/run-bounded.test.mjs` cover silent CPU
work, output versus absolute limits, real failures and signal statuses, missing
commands, cancellation after leader exit, phase reporting through pytest capture,
and routing under conflicting inherited ledger settings. The legacy merge-agent
prompt uses the same helper and release-on-failure contract. The routing fixture
checks that explicit disposable-test DSNs/opt-ins and pytest options survive;
no new skip logic is added. The original five-file integration selection fails
closed in the provisioned companion checkout because that baseline lacks
`test_build_completion_supersede.py`. The four available incident slices run
separately; their source and outcome are recorded in the
ticket/PR evidence separately from the historical source head.
`test/fixtures/validation/pytest_phases.py` additionally exercises the real pytest
plugin with conflicting inherited runtime settings: the ordinary run must pass,
and `HAM_VALIDATION_FIXTURE_FAIL=1` must retain pytest exit 1.
