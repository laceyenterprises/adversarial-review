# LAC-2258 — publication workspace reconciliation

## Summary

In the Agent OS #11247 rescue, the publication checker ran Git in the
non-Git worker root even though HQ had provisioned a selected repository
beneath it. An offline regression reproduced `committed-unpublished` while
the live PR head already contained all remediation patches.

## Interface changes

The HQ publication checker resolves the checkout through the recorded
launch's owner-scoped dispatch status. It verifies the selected worktree
origin and the live PR and destination ref before accepting structural replay
proof. A conflicting or unreadable terminal destination preserves the source
job. Publication leaves findings, round accounting, and the signed
source-policy and merge gates in force.

LAC-2193 fixed missing HQ provisioning and established manifest custody for
final fix-all. This change uses that custody check for those workers and
requires owner status to identify the checkout before running Git. The live
launch, receipts and historical job remain under their existing owners.
The operator-owned historical generated-index replay still verifies its
explicit proof workspace at the withheld head.

The final comment-only remediation accepts mixed string/number round identities
when the worker descriptor is stored only on its round. Workspace resolution
normalizes a null environment before owner-status, root and manifest checks.
Missing or invalid live destinations retain the unavailable diagnostic rather
than reporting concurrent head movement. Ended-round recovery still refuses
network publication without an explicit worker environment.

for the work slot, despite an independently observed live PR head. Fixtures
exercise a selected repository alongside another checkout, wrong and ambiguous
associations, missing status and copied manifests, head movement, incomplete
destination evidence, and source preservation on a failed terminal write.

  HQ publication, final-round completion, generated-index replay and the
