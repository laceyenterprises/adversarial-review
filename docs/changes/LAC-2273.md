# LAC-2273 — Bound the native legacy writer's PR identity read

## Summary

`runLegacyPrWrite` reused the full merge-agent candidate builder even though
it consumed only PR state, head and base. The wrapper's evidence timer rejected
the wait without passing its signal into the builder. Open candidates can run
the stacked-base guard, which can still persist a hold after that rejection.
The candidate builder's own all-settled barrier only governs its return.

The native wrapper now delegates to one live, owner-aware, metered PR identity
read. The existing evidence budget covers the request, and the transport receives
the cancellation signal and remaining child timeout. Normal scoped rate-limit
admission can defer the read instead of sleeping through the evidence budget.
The authority caller still evaluates the full eligibility evidence. Native route
selection, issuance locking and command custody continue through the existing writer.

## Interface changes

The internal `readCandidate` seam receives `{ rootDir, signal, timeoutMs }`.
Malformed/mismatched identity now refuses with
`malformed-or-mismatched-identity`; valid terminal or moved-head evidence retains
`terminal-pr-or-head-changed`. CLI flags, exit 75 and ledger schema are unchanged.

Final comment-only remediation adds offline cross-owner mint coverage, including
the selected role/owner, child token environment, unchanged source environment,
and expiry during a delayed mint preventing a late PR transport launch. Shared
mint cancellation is deliberately deferred: a per-caller abort must not cancel
other waiters on the per-role/owner single flight. Existing per-broker timeouts
remain authoritative for mint lifetime.

Admission remains non-urgent by default because the wrapper accepts arbitrary
legacy commands and cannot prove closure eligibility. It preserves an existing
caller scope, including closer urgency, but the standalone CLI does not consume
the closer reserve. No lifecycle states, smoke promises or deployment steps change.
