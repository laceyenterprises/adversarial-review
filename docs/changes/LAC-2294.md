## Summary

Rundix19's follow-up job stayed pending with `no declared reader role`. The
normal reviewer handoff carried a family such as `claude`. Posted-review
recovery preferred `reviewer_passes.reviewer_model`, which held the concrete
execution model `claude-opus-5-5`. The alternate-owner reader treated that value
as a family key and refused before broker selection. No worker spawned.
Root stopped the unclaimed job through the native follow-up stop path.

## Interface changes

The posted-review artifact and the follow-up job carry a declared
`reviewerRole` separately from the model. The existing reader selector is
shared by branch admission, workspace preparation, contamination audits,
guarded publication and auth recovery. The guarded publisher accepts
`--reviewer-role` alongside `--reviewer-model`. Exact legacy identity evidence
remains supported and unresolved identities hold before broker selection.
New jobs also persist the recognized legacy role when the caller omits it,
including `claude-opus-5-5`; explicit role evidence remains unchanged. Generated
publisher commands include `--reviewer-role` only for non-empty strings.
