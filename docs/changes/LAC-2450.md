# LAC-2450 — Prove an obsolete catalog projection

## Summary

Agent OS #11682 retained its branch-push divergence record in the
authoritative catalog fragment. Its candidate `catalog.json` had returned to
the merge-base bytes for main to regenerate after merge. The author had
mirrored one record addition in the projection, so primary-change preservation
reported that stale output as an unauthorized reversal.

The proof reads the pinned assembler from the live Agent OS `main` base and
replays the domain transformation over immutable regular blobs. It requires the
entire protected catalog to match that one-record replay and the candidate
catalog to match the merge-base blob. The authoritative fragment must retain
the record's key and field names and match its source and documentation values.
Ordinary source preservation still applies to all protected files. Both live
reads must agree on the base and candidate head.

Final review remediation shares the sibling catalog proof's read-failure
classifier and adds bounded, fixed-reason skip diagnostics. A preflight skips
all proof reads unless both comparisons modify an authoritative fragment.
The closure runbook records the 14-file/48-tree/14-blob maximum before cache
reuse and the conservative parser's refusal of some valid numeric spellings
and integer-like key orders. Fence tests invoke the proof directly and assert
both the reached fence and its position relative to blob reads.

## Interface changes

Successful primary-change results can include `catalogProjectionPreservation`
with the recipe digest, refs and input and output blob identities. This
evidence is transient and is recomputed on each gate read.

## Verification

The fixture uses synthetic Git history served through the offline immutable
blob reader. It exercises recipe trust, exact output and fragment identities,
malformed evidence, source reversals and live head movement. A read-only check
of the immutable Git objects for #11682 confirmed that replaying the one
domain produces the protected catalog bytes and that the candidate matches
the merge-base blob.

The catalog projection, catalog field placement and legacy generated
preservation suites passed all 79 tests. `npm run lint` reported zero errors
and 147 existing warnings. `npm run typecheck:contracts`,
`bash demo/research-finding-walkthrough.sh` and `git diff --check` passed.
