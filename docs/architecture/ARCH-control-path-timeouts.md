# Hammer/closer timeout inventory — TIMEOUTSWEEP-01

This is the companion to agent-os TIMEOUTSWEEP-01. The operator approved
"Yes on timeout hardening sweep." and then provisioned this repository.
"If a contract is broken we should first and foremost fix the contract."

A timeout means unknown: scale it with load, and never turn it into a final or
stored verdict. Use the existing `loadAwareTimeoutMs` with the nominal base,
exactly once before consuming it; clip effective waits to outer deadlines.
Queue polls, backoff, freshness, lease TTLs and the 25-hour companion dependency
SLA are policy windows, not per-operation waits, and stay fixed.

This first slice converts publication, process evidence, companion reads and
cleanup. The table includes wait/deadline expressions in `src/ama/`, plus the
publication CLI and watcher entrypoint families, to expose remaining caller
work. It deliberately keeps already-effective budgets and policy intervals
visible so a follow-up does not scale them a second time. Source references are
a snapshot, not a generated guard. Comments are excluded. Untraced callers are
explicit follow-ups: their current verdict has not been certified by this slice.
The size allowance defers those complete caller slices; no new gates/config or
workflow changes are added. Tests and operator-only CLIs are out of scope.

The HCP memory search timed out on resume. Local closure/hold runbooks and the
supplied incident history informed this slice; unavailable memory evidence is
not evidence that no matching scar exists. All tests use synthetic identities
and fixture paths. There are no live service, ledger or recovery actions.

Validation: 142 cases pass across the eight scoped test files (the new
control tests plus submitter, companion, cleanup/liveness, publication/CLI and
withdrawal-currency fixtures). All ran with netguard and VDB=false, at most two
workers, bounded to 180 seconds per command. ESLint reports zero errors (existing
warnings elsewhere remain); touched files have no lint findings. Contract
typecheck and git diff --check pass. Full service suites and the walkthrough
were not run under the ticket's explicit touched-tests-only constraint.
