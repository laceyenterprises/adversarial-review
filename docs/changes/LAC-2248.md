# LAC-2248

## Summary

Follow-up Git operations now select the repository owner's declared GitHub
route. This addresses the pre-spawn smart-HTTP clone failure seen after the
submitted review of Rundix/rundix PR 4.

## Interface changes

Alternate-owner clone and fetch use the recorded reviewer's read route.
Publication resolves the selected harness's owner-scoped write installation,
including the workflow capability when required, and uses the inspected commit
and exact remote lease. A missing or refused capability produces
`remediation-owner-auth-hold`. The pending job or retained unpublished commit
keeps custody. See the [follow-up runbook](../follow-up-runbook.md#alternate-owner-follow-up-git).

## Verification

The offline two-owner fixture passed all 14 cases using synthetic tokens and
fake transports (`node test/run-tests.mjs test/remediation-owner-auth.test.mjs`).
Lint passed with zero errors, contract typechecking passed, and the offline
research walkthrough produced three byte-stable deliveries. It covers clone, fetch, publication identities, workflow write
authority, refusal, missing pins and budget-neutral custody. Runtime activation
and an organic follow-up remain separate acceptance steps.

The final CI repair preserves source-token revocation for legacy selector
callers, including cached owner clients. Only the declared follow-up read route
explicitly selects broker authority without requiring a home token; its role
whitelist and owner-scoped broker checks still apply. The existing harness
identity enforcement policy moved verbatim into
`src/remediation-identity-policy.mjs`, with the same monolith re-export and
fail-closed defaults, keeping the main module within its unchanged line limit.
These repairs add no grants, identity fallback or timeout/line-limit waiver.

The adjacent legacy writer CI fixture race is repaired and measured separately in
[LAC-2253](LAC-2253.md); it changes no owner-routing or runtime contract.
