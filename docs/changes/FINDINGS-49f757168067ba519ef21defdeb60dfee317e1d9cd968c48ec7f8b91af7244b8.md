# FINDINGS-49f757168067ba519ef21defdeb60dfee317e1d9cd968c48ec7f8b91af7244b8

## Summary

The published-head and merge-lease PR probes in `bin/hammer-verify-head.sh`
drain filtered stderr with `grep -Ei ... >/dev/null`. Early-exiting `grep -q`
could cause upstream `sed` to receive SIGPIPE under `pipefail`, misclassifying
a transient GitHub read failure as permanent when stderr exceeds the pipe buffer.

Offline regression tests execute both rendered helpers with an early HTTP 502
match followed by more than 1 MiB of stderr. Each helper retries two transient
failures and accepts the third read; retry sleeps are stubbed.

## Interface changes

None. Existing retry budgets, permanent-failure behavior and merge gates remain
unchanged.
