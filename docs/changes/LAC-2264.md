# LAC-2264 · Cold live-pack merge preflight

## Summary

The installed `bin/live-pack-check.mjs` entered the shared live-pack evaluator
before preparing the review app's read context. The saved cold run for
`agent-os#11150` refused because worker observations were disabled. With the
existing app session prepared in the same process, the native evaluator cleared
the recorded heads of `agent-os#11150` and `agent-os#11196` with `waived: false`.

The CLI now prepares the declared `adversarial-review` app read context after
validating identity, reading the current PR and listing changed files, and
only when a guarded build pack is touched. The entry-point audit found that
`repair-in-place` and the GSR lease release already prepare their context. The
hammer remediation guard has a tested conservative policy for inconclusive
liveness. The observed cold merge-preflight failure was specific to
`live-pack-check.mjs`.

## Interface changes

`node bin/live-pack-check.mjs OWNER/REPO PR HEAD` returns exit 1 with JSON
containing `ok: false`, `reason: "dispatch-context-unavailable"`, and a fixed
redacted `detail` when a touched pack requires an app session that cannot be
prepared. It returns before reading plan contents or liveness. Malformed
identity fails before all network reads, and PRs without guarded pack files
clear without registration. The existing exact-head and approval checks remain.

`checkLivePackMerge` accepts an optional `prepareReadContextImpl` callback,
invoked only after identity/current-head validation and guarded-path discovery.
`prepareDispatchReadContext` accepts opt-in `maxAttempts` (default one); the CLI
requests at most three attempts for transient failures, sharing the original
load-aware eight-second deadline including backoff and HTTP timeouts. Permanent
credential/entitlement failures still refuse immediately with fixed redacted
details. See the [closure runbook](../RUNBOOK-ama-closure.md#operator-label-closure-holds-labelgate-01).

## Current-main integration

The failed Node 22 workflow on the earlier published head exhausted the fixed
900-second suite budget; it predates the merged offline fixture-performance
repair. This integration retains the final live-pack remediation and imports
that reviewed performance repair from current main. It does not rerun the
unchanged failing head, increase the suite deadline or waive Node 22. All 135
focused live-pack/context/retry cases pass after the integration. Required full
hosted Node 22/26 checks still apply to the new merge commit.
