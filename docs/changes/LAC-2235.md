## Restoration procedure for root

1. Re-read the open PR, exact head and base, current source owner, and closer
   lease. Keep the original uncertain workspace retained. Recompute strict
   preservation if either comparison endpoint changes or the report below
   predates the current head.
2. Use the existing [R05 repair route](../STATE-MACHINE.md#msm-two-path-merge-authority-current)
   where native admission selects it.
   `node bin/primary-change-context.mjs OWNER/REPO PR HEAD --diagnostics`
   collects evidence. The existing
   `primaryChangeRepairEvidence` helper in `src/ama/primary-change-repair.mjs`
   enumerates the refused paths and projects the units into the primary
   snapshot. For each unit, restore the corresponding primary change against
   the current tree while keeping the behavior required by the reviews.
   Take only the relevant hunk from the primary snapshot. Ranges in this
   record are half-open merge-base coordinates. Equal endpoints identify an
   anchor. The primary snapshot selected by the gate can differ from the
   review's own commit.
3. Stage candidate restorations under root custody and check the cited behavior
   before any publication. If a unit and a completed finding cannot both be
   preserved, keep the hold and bring that exact conflict to the operator.
   Keep the decision scoped to the repository, PR, base, head, exact units,
   and cited findings. This record supplies no policy authorization.
4. If a candidate satisfies both, use the admitted builder fast-forward
   repair at the expected head. Run strict preservation again on the
   resulting head and retain finding dispositions, exact-head required CI,
   and ordinary closure checks. A closed or merged PR needs no recovery.
   Leave exhausted rounds charged and keep the existing refusal if the
   restoration route is unavailable.
