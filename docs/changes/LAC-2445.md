# LAC-2445 — Reuse immutable work in strict source history reads

## Summary

Three strict native reads on deployed adversarial-review `2c9ee2ef4` exhausted
the history budget for Agent OS #11647 at `4927f728`, #11675 at `5f2eef46`,
and #11682 at `5c0cdada`. All three incident receipts recorded
`history-read-failed` and `historyReadTimedOut: true`.

Author, cited-review and reversal-parent snapshots now resolve their merge base
and reconstruct complete inventories without paging commit ranges whose
contents are unused. Live-head classification, historical reversal search and
completed source-remediation proof still read their required ancestry. The
reader reuses identical per-file Git diffs after independently establishing
each snapshot's changed paths. Authentication and quota refusals on recursive
tree reads propagate through the existing history failure path.
An unusable citation file list or unsupported changed object rejects that
waiver while retaining the protected author evidence. Mandatory snapshot
failures, immutable-data integrity failures, and infrastructure errors still
stop the history read.

## Interface changes

Required patch-only snapshots reconstruct inventory from immutable tree
observations and can resume individual file checkpoints. The whole-operation
deadline covers reconstruction, checkpoint reuse and proof collection. Each
evaluation checks the live PR and uses the existing review and provenance
rules to establish source authority.

## Verification

The offline benchmark uses `LAC_2286_LARGE_HISTORY=1 node test/run-tests.mjs
test/history-read-throughput.test.mjs`.

On the offline 205-commit fixture with 353 changed paths, the preserving case
went from 706 Git diff invocations to 353 and from six compare requests to
four. Total API reads went from 718 to 716. The single-file benchmark run
measured 5.05 seconds before and 1.12 seconds after. The evidence and verdict
digest was identical. The reversal case still refused with identical evidence
and 353 diffs, and used four compare requests instead of six.

An authenticated read using the patched worker checkout for Agent OS #11647
at `4927f728b2f362a22899fb0e48bf5b4cec437c86` completed in 133.9 seconds
under its effective 275.0-second budget. The native collector produced
complete inventories of 18 primary and 1,287 final paths. The strict verdict
was `primary-change-reverted`. The reader started 2,025 API reads, including
2,005 blob reads, and invoked Git diff 1,303 times. These are worker-side
measurements from a disposable history root. Production deployment, authority
state and the other two strict reads still require operator verification.
