# LAC-2252 — Preserve a moved PR head during hammer publication

## Summary

On PR #1955, a closer whose local commit was an ancestor of the PR tip reused
that tip as a fresh Git lease after the API publisher refused. The Git push
rewound the branch and discarded a concurrent operator repair. The physical
lease confirmed the current tip while the candidate's ancestry proved the
update would discard it.

## Interface changes

The API publisher returns `git-fallback` only for a source-checked,
pre-mutation compatibility decision. The Git publisher takes the immutable
candidate, branch and expected source SHA, independently rechecks them, and
refuses a strict ancestor of the remote tip. It still accepts proved clean
rebases and source-bound conflict repairs. Equal tips produce no new edge.

Moved heads use the existing `head-changed` outcome. Unavailable proof,
identity or source reads use `source-publication-refused`. Both stop the
current closer and retain local commits. Verified API writes with scratch
adoption failures retain their existing attestation and stop behavior.

The sibling sweep also pinned the standalone merge-agent's Git lease to its
pre-rebase source. The server-side branch update already uses the original
expected-head CAS. The identity-only amend retains its exact pre-amend lease;
the queue, remediation and auth-recovery publishers submit pinned candidates
against the captured source, independently of the hammer's API disposition.

Final comment remediation keeps local rewrites deliberately narrow: exact
replay or the exact conflict-repair head, without follow-up commits. New
offline regressions cover rebase-plus-commit and a real conflict resolution
followed by a commit. The hammer prompt now orders remediation before the
server-side rebase and describes refusal recovery; the merge-agent prompt
requires a captured SHA in an explicit lease for local conflict publication
and explains the controller's ancestry-refusal exit 20.

Missing or malformed captured source evidence now uses the closer-origin
`source-publication-refused`, while a valid different source remains
`head-changed`. After an API mutation failure without a returned SHA, a
bounded source-branch read classifies observed movement as `head-changed`.
It grants no Git fallback and does not adopt the foreign head or clear
uncertain custody: branch movement cannot disprove an ambiguous write.
The runbook, README contract paragraph and lifecycle declaration describe
these outcomes. No store shape, lifecycle value or smoke promise changes.
