# LAC-2176 — deterministic HAMLANEWAIT-01 transfer handoff

## Summary

The transfer-wake fixture combined a `setImmediate` handoff, native filesystem
notification delivery, a three-second deadline, and a 1.5-second elapsed-time
assertion. That made its route-fencing result depend on host scheduling and wake
delivery. PR #1761 reported one full-suite HAMLANEWAIT-01 failure followed by an
all-green isolated routing rerun. The repository's
`docs/postmortems/evidence/LAC-2145/full-node26-incomplete.json` also records this
transfer fixture failing after about three seconds.

Use the existing injected clock to release the held lane lock during the waiter's
post-subscription acquisition recheck. The first clock read proves contention;
the second releases the lock and advances the fixture clock by one second within
its original deadline. Assert that the handoff happened, the stale legacy route
is refused, the durable route remains queue-v2, and no legacy writer intent was
created. Native filesystem wake delivery remains covered by the existing
cross-process owner test. No custody or mutation of PR #1761 is involved.

## Interface changes

None. Only the offline transfer fixture changes. Production wait deadlines,
notification behavior, ownership, and routing semantics are unchanged.
