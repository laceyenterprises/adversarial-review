# LAC-2432 — Withdraw canceled daemon merge waiters

## Summary

An abandoned reservation for Agent OS #11698 blocked the next ready closer
while the `main` lane had no holder. The 05:36 UTC native status showed an
OPEN PR's waiter in position 1 with a `notBefore` backoff after a no-merge
release. The watcher logged the 45-second coexistence deadline, the
40-second clean-merge operation timeout and two failed live gate/configuration
reads. The operator's 05:40 UTC report confirmed target absence after invoking
native cleanup. The original API result could not be retained because writing
the receipt failed. The report confirmed no holder preemption or worker stop.

The clean-merge adapter now passes the operation's cancellation signal to
the lease retry loop. The acquisition owner records each persisted waiter
before the native call can fail at a later step. On cancellation or failure,
it compares only that registration through the native `expectedWaiter` CAS.
Outer scopes compare entry snapshots so late settlement preserves a newer
registration. The native release path keeps backoff and audit accounting
while skipping requeue for a canceled holder. The holder release fence and
the usual eligibility, source, review, protection and CI checks still apply.
When release requeues before a later cancellation, the concrete operation
keeps the returned snapshot through settlement and withdraws it via CAS.
Final comment-only remediation also withdraws matching entry-time snapshots
when cancellation precedes registration. Same-timestamp refreshes remain
protected by the full snapshot comparison. An interrupted holder without a
release outcome records `operation-aborted` instead of `holder-exception`;
ordinary exceptions and explicit outcomes retain their reasons.

LAC-2087 established concrete-operation ownership across a soft caller
deadline. LAC-2098 established that a live service or parent process does
not prove the acquisition is active. LAC-2196 added exact-snapshot cleanup
with live terminal PR evidence. This fix uses operation cancellation as the
proof for an OPEN PR and leaves the terminal reconciliation path in place.

## Interface changes

`withDaemonMergeReservation` passes a registration observer to its owner.
Native daemon registration adds an optional `registrationId` UUID to
distinguish same-millisecond refreshes without changing arrival order.
`releaseMergeLease` accepts `requeueDaemonWaiter: false` for a canceled daemon
holder. A normal daemon requeue returns its snapshot as `requeuedWaiter`.
Legacy waiters remain readable.
The final remediation adds no public interface or durable shape changes;
`operation-aborted` uses the existing free-form history reason.
