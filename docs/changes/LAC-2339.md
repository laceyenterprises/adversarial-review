# LAC-2339 — Reuse the failed final-fix reservation

## Summary

The repair companion now supports the HQ-owner retained final-fix submission.
It reads the exact key with the original project and repository grant and
rechecks queue and closer custody. A compare-and-read returns the same
unbound epoch, leaving prior spend and ownership observations intact. Worker
Pool provisions and admits the recovery under that key, and the existing
review flow recognizes publication through native produced-head evidence.

[Final-round remediation spec](../SPEC-adversarial-review-auto-remediation.md)

Final comment-only remediation rejects ineligible retained owner states before
dispatch preparation or lookup. The AMA closure runbook now describes the
recovery epoch argument and protocol discovery invocation.

The Hammer closeout adds recovery-only refusals for missing or closed review
rows and mismatched recorded heads. The spec describes the Worker Pool
checks for failed-job identity and enqueue history, and the legacy retirement
tool's key scope.

## Interface changes

The optional tenth CLI argument selects the retained recovery epoch;
`--final-fix-recovery-protocol` advertises `final-fix-recovery-v1`.
This remediation documents those existing interfaces and preserves the locked,
read-only comparison and persistent store shape.

## Live head evidence after final remediation (2026-11-24)

The first deployed recovery attempt for Agent OS #11565 safely refused
`final-fix-head-mismatch`. GitHub and the original failed producer both name
`245623bc54299303b2078de79938c9b7135bbfd9`, while the review row correctly retains
the delivered review at `8ac8a1ebca55b3d02de5d397bdd1d2e8ebef3a74`. Comparing that
review revision with the later publication prevented legitimate recovery.
The deterministic fixture reproduced the same refusal before this repair.

Retained recovery now uses the existing bounded, repository-scoped live GitHub
identity reader. It checks the exact open head before owner reconciliation and
again after canonical scoped absence, before rechecking custody and replaying
the unchanged epoch. Unknown reads, closed or moved heads and newly claimed
follow-up work still refuse. No review row, original failed producer, workspace,
reservation, spend or attestation is rewritten. Ordinary repair admission is
unchanged. The runbook and retry-ledger model document the evidence distinction;
there is no data schema or public CLI signature change.
