# LAC-2439 — Resolve alternate-owner publication through the GitHub adapter

## Summary

HQ's broker preparation no longer exports owner, App or installation pins.
The old publisher rejected that output before minting, even when the configured
role and broker route were ready. The publisher now uses the same
repository-aware GitHub App resolver as HQ worker publication and checks the
granted permissions from the broker response that supplied the token.
Alternate-owner workflow preflight also requires the declared reader and uses
the guarded publisher route when called without a prepared read route.

## Interface changes

No new config keys or lifecycle states. Publication requires the canonical
resolver, a broker-enabled harness role, a verified installation for the
target owner, a live token and the required write grants. See the
[publication and runtime acceptance procedure](../follow-up-runbook.md#alternate-owner-follow-up-git).

## Verification

- The pinless synthetic route reproduced `remediation-owner-auth-hold` before
  any mint on the prior implementation. The same configuration reaches guarded
  publication after the fix.
- The owner-route tests cover mismatched identity, missing permissions or expiry,
  workflow escalation, PAT refusal, legacy configuration and the exact Git lease.
- `npm test --` over seven affected test files passed 634 tests. An offline
  check against the parent GitHub adapter with synthetic config and a mocked
  broker passed four cases.
- `npm run lint` reported zero errors, `npm run typecheck:contracts` passed, and
  `bash demo/research-finding-walkthrough.sh` produced byte-stable transcripts.
