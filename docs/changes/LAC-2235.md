# LAC-2235 legacy source-preservation recovery

## Summary

Use the existing primary-change restoration path for legacy reversals whose
original publication authority cannot be verified. The Agent OS PRs below
remain in root custody. This record gives root the protected units to inspect
and the completed findings each repair must preserve.

The native final-fix-all gate needs the original queue job bound to the
repository, PR, and reviewed head, plus a verified produced attestation at the
authorizing SHA from that job's launch and worker class. It verifies the
review identity, finding coverage, and patch separately. Native
`hq attest chain` returned zero rows for all five PRs in this investigation.
`hq pr adopt` recovers PR identity from an existing launch and push. It
cannot turn an independent publication into the historical final-fix-all
job. The LAC-2232 receipt records ordinary branch completion at
`7dc44fba2683736863bee396b98409cabed51f7d`. The worker completed it on
`codex/rescue-11153-prefix-20261120`, while PR #11153 still pointed to
`9f1ec9b7f3b4952e2254bc114708a889880570ec`. The receipt supplies neither
the PR binding nor custody for the earlier authorizing commit.
[Native final-fix-all contract](../RUNBOOK-ama-closure.md#final-findings-remediation-through-the-builder-laneauto-01)

The existing HAM path requires an authoritative citation and authenticated
commit provenance. For superseded citations it also requires the original
reversal and its protected region to be established. An App publication edge
can carry a verdict forward under the stale-head rules. It supplies no
missing finding citation or protected region proof. A clean later review
likewise leaves the historical refusal intact. The future identity writer
repair in #11240 applies at new provisioning and publication. This
recovery covers legacy source reversals. LAC-2254 owns the generated
main-integration evidence for #11175 and #11150.

## Restoration procedure for root

1. Re-read the open PR, exact head and base, current source owner, and closer
   lease. Keep the original uncertain workspace retained. Recompute strict
   preservation if either comparison endpoint changes or the report below
   predates the current head.
2. Use the existing [R05 repair route](../STATE-MACHINE.md#msm-two-path-merge-authority-current)
   where native admission selects it.
   `node bin/primary-change-context.mjs OWNER/REPO PR HEAD --diagnostics`
   collects evidence. The existing
   `primaryChangeRepairEvidence` helper in `src/ama/primary-change-repair.mjs`
   enumerates the refused paths and projects the units into the primary
   snapshot. For each unit, restore the corresponding primary change against
   the current tree while keeping the behavior required by the reviews.
   Take only the relevant hunk from the primary snapshot. Ranges in this
   record are half-open merge-base coordinates. Equal endpoints identify an
   anchor. The primary snapshot selected by the gate can differ from the
   review's own commit.
3. Stage candidate restorations under root custody and check the cited behavior
   before any publication. If a unit and a completed finding cannot both be
   preserved, keep the hold and bring that exact conflict to the operator.
   Keep the decision scoped to the repository, PR, base, head, exact units,
   and cited findings. This record supplies no policy authorization.
4. If a candidate satisfies both, use the admitted builder fast-forward
   repair at the expected head. Run strict preservation again on the
   resulting head and retain finding dispositions, exact-head required CI,
   and ordinary closure checks. A closed or merged PR needs no recovery.
   Leave exhausted rounds charged and keep the existing refusal if the
   restoration route is unavailable.
