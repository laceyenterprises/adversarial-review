# FFACUSTODY-01 — final-fix-all launch custody

## Summary

Agent OS [#10762](https://github.com/laceyenterprises/agent-os/pull/10762)
and [#10780](https://github.com/laceyenterprises/agent-os/pull/10780)
reported successful final-fix-all publication followed by
`hq branch-push complete` refusing a checkout without `workspace.json`.
The former also reported an absent canonical worker manifest. Both PRs were
already merged when this investigation read their state; their branches and
owners were left untouched.

The launcher allowed local remediation while the prompt required an HQ
branch-push completion and the preservation gate required a produced
attestation from the durable owner launch. A local reply storage key was
insufficient: no HQ worker provisioning occurred on that path. This change
fixes the launcher in adversarial-review rather than manufacturing the missing
Agent OS records.

## Interface changes

Final-fix-all selects HQ even when native configuration, health failover or
pre-spawn sticky bookkeeping selects local. A defensive runtime check also
refuses direct local spawn. The HQ owner read uses the selected environment.
This lane uses direct HQ dispatch with explicit PR/branch/root and
`--idempotency-key ffa-<sha256(jobId)>` on the initial attempt. A durably
settled worker retry salts the next key with its previous LRQ; launcher
crashes and pre-spawn reclaims do not advance that attempt. Retries after
enqueue reuse the work order even if the prompt path or proposed class changes.
The returned actual LRQ and worker class are persisted
without a status read that could fail while provisioning is pending.

The worker descriptor carries `requiresProducedAttestation`, `hqOwnerUser`,
`custodyRepo` and `custodyBranch`. Before reconciliation inspects a workspace,
the canonical slot and manifest must match the recorded launch and these
bindings. Topic paths and copied manifests cannot bypass that validation.
The existing produced-attestation reader and lane-reversal gate retain their
exact-head, class and launch checks. No signature, launch record or manifest is
fabricated. Legacy local owners are not migrated or redriven by this change.

Final comment-only remediation aligns the config dispatch-path helper with the
HQ-only runtime override. Workspace custody falls back to the caller's `HQ_ROOT`
when the worker descriptor omits `hqRoot`, while explicit roots remain
authoritative. Offline regressions cover both workspace-resolution paths and
queued provisioning refusal followed by successful resolution, without worker
state mutation. No persistent fields or lifecycle/smoke contracts change.

Agent OS was inspected as the declared secondary repository: its dispatch
supports stable idempotency keys, provisioning owns workspace identity, and
`hq branch-push complete` owns produced-head emission. No companion source
change or gitlink bump is needed.
