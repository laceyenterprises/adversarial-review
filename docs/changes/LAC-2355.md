# LAC-2355 — Account for a completed follow-up in source authority

## Summary

The primary-change gate can account for one verified documentation-only final
follow-up between an exactly replayed review and its first HAM repair. The
proof pins the review, base, commit parents, worker publication and complete
file deltas. Missing or inconsistent evidence preserves the refusal.
Transient publication reads use the existing retryable history-read hold.
Malformed optional tree evidence leaves the main reader and its progress intact.
Malformed stored replies retain the ordinary parent-patch refusal, and damaged
matching completed-job records prevent source-parent uniqueness proof without
discarding other round evidence. Complete non-transient GraphQL errors also
refuse the optional proof, including when `gh` exits nonzero; transport, quota
and auth failures remain retryable.

## Interface changes

No caller or configuration changes. The proof is evaluated from live review
and publication evidence and immutable Git objects. The worker App lookup
uses the reader's environment. Strict finding coverage and removal-content
checks still apply.
The shared HAM-head classifier's `authOutage` and `HISTORY_READ_INVALID`
propagation applies to existing range, content-rebase and fleet-force-push
proofs as well as this publication proof. These errors now hold for retry,
including repeated deterministic invalid-history failures. The parent proof
ends when a second HAM commit lands. The runbook documents its repeated
per-evaluation scan, timeline and inventory bounds.
