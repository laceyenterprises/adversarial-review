# LAC-2229 — Preserve a catalog field moved into identity order

## Summary

On Agent OS PR #11177 the protected head `fd8f6fe868bf` put
`terminalCheckoutRecoveryContract` on line 2 of the generated catalog. Final
head `33b03f9c72d3` put the same value on line 18080, following the documented
append-by-identity rule. The single-key canonical fragment was identical at
both heads. The strict line predicate refused the old insertion anchor.
With the published Git objects available locally, the existing generated
proof still returned `manifest-absent`.

The Agent OS GENCONFLICT inventory owns the catalog projection for conflict
regeneration. The primary-change gate now proves only the standalone
insertion of a new top-level string that moved into the documented order.
Unrelated catalog edits remain protected. This follows the same principle as
the mechanical migration proof, which binds the movement to immutable source
and destination content. The catalog proof reads data and needs no generator,
reversal citation or operator receipt.

## Interface changes

The shared primary-change collector can return exact-head evidence for this
catalog insertion. The [closure runbook](../RUNBOOK-ama-closure.md#agent-os-catalog-field-placement-lac-2229)
defines the evidence. LAC-2224 handles generated-proof preflight separately.

## Verification

`test/primary-change-catalog-field.test.mjs` builds an offline commit sequence
and runs the shared collector and strict predicate. It checks the original
refusal, the exact insertion proof, stale proof identities, changed or absent
values, duplicate keys, altered ordering, unsupported ownership, tampered
blob responses and a reverted edit outside the insertion. The production
history-reader path is exercised without a local checkout.

A read-only `fetchPrimaryChangeContext` replay against PR #11177 used the
published objects in a scratch clone and compared 30 protected files against
380 final files in the original author merge-base coordinates. Without the
new proof the strict predicate returned `primary-change-reverted` at catalog
insertion `[2, 2]`. The existing generated proof returned no evidence.
With the new proof the strict predicate returned `ok: true`. This verifies
that predicate for those object identities. A second native replay through
the production history reader, with no local clone input, returned `ok: true`
for the same insertion and heads. Live closure requires the reviewed
deployment and the ordinary exact-head merge checks.
