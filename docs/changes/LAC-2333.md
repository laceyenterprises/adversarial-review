# LAC-2333 — Preserve published remediation through CI read failures

## Summary

AR #2030 and Agent OS #11477 both published remediation, then received
`stopped (no-progress)` comments while check observation was still pending.
The #2030 worker also reported an HTTP 401 from the bounded check watch.
Once the final-round reconciler independently proves publication, these
reports now retain the source edge and use the existing watcher handoff.
The watcher observes the published head through managed GitHub reads.
An unresolved permission or policy denial retains unknown CI and names
the operator for recovery in the PR comment, without a separate page.
Legacy CI-titled blockers whose prose requests approval or credentials remain
human-owned, even on a proven final publication. A `pending-ci` tag also keeps
explicit approval requirements human-owned. The auth classifier accepts raw
error strings, the historical auth-failure entry accepts a null kind, and
published-round metadata falls back to the job revision when the plan is absent
or malformed.
The Hammer closeout requires independent push proof before a legacy read-only
CI watch report can bypass GitHub publication recovery.

Hosted CI repair moves credential-error classification into a shared pure
module so watcher fixtures can replace GitHub CLI I/O and still load the
classifier. The publication-recovery filter and published-round metadata
assembly live with their respective consumers, keeping the reconciliation
module within its existing line limit.

Public witnesses: [AR #2030](https://github.com/laceyenterprises/adversarial-review/pull/2030#issuecomment-7092916408),
[Agent OS #11477](https://github.com/laceyenterprises/agent-os/pull/11477#issuecomment-7091833286).

## Interface changes

The terminal job and round can contain `completion.publishedCiObservation`.
It carries the exact source head, observed check identities when readable,
historical watch status and current observer or recovery ownership. The
validated worker reply retains historic check names and run IDs. The public
comment reports the source effect and current successor. The existing proof,
review admission, closer and required-check gates still apply. The shared CI
probe treats an empty external rollup as unknown. Re-review admission and
`ci-blocked` release therefore wait for external check evidence; an operator
must resolve admission for a repository deliberately without external CI.

## Verification

The offline regression first reproduced a `stopped` closeout after independent
push proof. The new cases exercise legacy pending evidence, approval requests
hidden under legacy CI titles, empty-rollup re-review admission, pending
followed by HTTP 401, subsequent green or red checks, permission denial, an unrelated
check head, missing source proof and a genuine operator-input blocker.
They assert the persisted source edge, public outcome and refusal to start a
second remediation on the completed final head.

- Scoped offline `npm test` for follow-up remediation and reconcile, final
  round completion and closer, closeout routing, PR comments and reviewer
  CI admission passed all 695 cases.
- `npm run lint` passed with zero errors and 147 existing warnings.
- `npm run typecheck:contracts`, the offline research-finding walkthrough,
  data-model catalog validation and `git diff --check` passed.
- Remediation reran the offline follow-up remediation file (411 cases) and
  blocker ownership, final-round completion and reviewer CI admission files
  (102 cases). Lint passed with zero errors; contract typecheck, catalog
  validation, the offline walkthrough and `git diff --check` passed.
- The hosted CI repair passed the Node 22 auth, CI admission, CI probe and
  ARC-19 suites (74 cases). On Node 26, those suites plus final-round
  completion passed (96 cases), along with 14 targeted follow-up remediation
  cases and 15 watcher claim and deduplication cases. ARC-19 reports the
  reconciliation file within its 4,297-line ceiling.
- The final repair brought the reconciliation file back within that ceiling
  after the Hammer publication-proof change. The offline ARC-19 gate
  verifies the existing limit.

- Final review regression coverage includes tagged approval under both pending
  and unknown CI, negated approval, a legacy null kind, raw GitHub error text,
  and the missing or malformed round plan fallback.

Runtime adoption and incident acceptance require an organic observation
on the normally deployed revision. Hosted exact-head required checks are
still required for merge.
