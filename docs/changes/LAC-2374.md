# LAC-2374 — Reduce startup in offline review tests

## Summary

On main `ef8d9d7542cd28aa31473df56f7fde3183b22841`, Node 22.23.5
selected 961 files and reached the 900-second deadline with 284 files
queued and eight active. The partial log emitted 19,719 top-level `ok`
records, including 51 skips, and zero `not ok` records. Node 26 passed.
[Node 22 job](https://github.com/laceyenterprises/adversarial-review/actions/runs/45571326296/job/139058413725) ·
[Node 26 job](https://github.com/laceyenterprises/adversarial-review/actions/runs/45571326296/job/139058413386)

The read-only disagreement report imports the log-path helper and the case-key
function from a module that depends only on Node built-ins. The shadow writer
shares the case-key function and retains both existing exports. Report
subprocesses avoid initializing the writer and its closure dependencies.

The offline rendered Hammer gate fixture drops an unused import of the
CI-blocked Hammer route. All six scenarios still run the rendered gate in
separate Node processes with the production review proof and eligibility code.

Final comment-only remediation adds `next-action-shadow-record.mjs` to the queue
runtime fingerprint beside the shadow writer, preserving coverage of the
relocated case-key and log-path implementations. The suggested import-boundary
guard is deferred because remediation operating rules reserve guard additions
for the operator; no new guard or CI configuration is added.

## Interface changes

None. Case keys, log location, CLI behavior, test identities, fixtures, and
assertions are preserved.
