# REVPOSTSTALL-01

A hosted reviewer now preserves each validated reply in
`data/reviewer-generated-reviews/` before its pre-post side calls. The record
is bound to the exact head, the producing model and bot identity, pass,
attempt, prompt stage and diff digest. The delivery phase up to the GitHub
write is bounded: 10 minutes nominal, load-scaled, capped at 20 minutes, kept
inside the Gemini process deadline, and overridable with
`ADVERSARIAL_REVIEW_DELIVERY_DEADLINE_MS`.

When the bound expires before any write has started, the reviewer emits a
`[reviewer-delivery-stall]` receipt and exits as `[reviewer-stalled]`. That is
the existing uncharged, claim-releasing class. The next same-binding claim
posts the preserved reply through the unchanged verdict-mode, grounding,
scope, exact-head post and capture path without rerunning the model. It keeps
the original execution and attribution and marks the record `delivered`.

`postGitHubReview` signals the write boundary immediately before the GitHub
write. Once a reusable record exists, that checkpoint must be durable or
publication is refused with the existing uncharged stalled classification. A
later delivered-bookkeeping failure cannot make the body reusable again.
Initial preservation without any saved record stays best-effort.
Records that reached the write are never redelivered blindly. Gates, routing,
CFG keys and governor and budget policy are unchanged.
