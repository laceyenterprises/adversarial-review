# LAC-2224: Check generated proof eligibility before checkout

## Summary

The generated-content proof fetched the exact head and base into a scratch
repository and checked out the entire head before inspecting the candidate.
That work could exhaust a Git command's load-scaled 15-second budget or the
proof's load-scaled 30-second budget before discovering that there was no
applicable declaration. An offline fixture that returned status 124 from the
bulk Git command reproduced `checkout-failed` on the original code. A local
replay of the original checkout for agent-os #11150 completed in 25.6 seconds.
The historical warning records the combined checkout stage, so the historical
timed-out subprocess is unknown.

The proof now reads the exact regular Git blobs it needs from the registered
local source. It opens a scratch worktree only after validating a matching
header or block declaration and the applicable base region. Immutable reads
disable lazy fetching, ref replacement and pathspec expansion. A surviving
candidate must still reproduce the output bytes, and block candidates must
preserve the bytes around the block. Cancellation terminates the checkout
process group before removing scratch.

## Interface changes

The same refusal can now report an eligibility diagnostic such as
`manifest-absent` even when a full checkout would have failed. An eligible
candidate that fails to materialize still reports `checkout-failed`.
Attribute-converted candidates that differ from their raw Git blob now report
`checkout-blob-mismatch` for both whole-file and block proofs. The closure runbook
documents this byte requirement, the accepted origin URL forms, and the distinct
pre-checkout input-marker and post-generation output-marker failure stages.
Scratch fetches only head and merge base; primary-head blobs remain source reads.

## Verification

Using the saved source-preservation contexts and immutable objects from the
registered clone, #11150's ledger baseline and #11175's App SDK inventory
returned `manifest-absent` in 143 ms and 114 ms respectively. Both retained
`primary-change-reverted` with zero generator calls. The final blobs begin with
JSON objects and neither merge base has a root `package.json`. The installed
registry lists the rendered state index and treats state inventories as inputs.
It lists neither refused artifact as a generated output. The saved patches
show a restored SQL baseline text/line pair and omitted SDK inventory entries
at the respective refused coordinates.

The offline regressions cover the bulk-command failure, cancellation during an
eligible worktree operation, exact regenerated bytes, missing objects and
protection of unrelated authored content.
The final comment-only round adds CRLF checkout-conversion regressions for both
proof paths, asserts that whole-file scratch fetches omit the primary head, and
uses bounded readiness polling for cancellation instead of directory watch events.
Its bounded run of `node --test test/primary-change-generated-files.test.mjs
test/primary-change-generated-blocks.test.mjs test/derived-artifacts.test.mjs`
passed all 62 tests. `npm run lint` passed with zero errors (149 existing
warnings), `npm run typecheck:contracts` and the offline research walkthrough
passed, and `git diff --check` was clean. The full local suite was not run;
PR-head CI remains the full-suite merge gate.

The follow-up review's missing-marker checkout concern did not reproduce:
`generatedBlock` throws for absent or ambiguous markers, and the candidate catch
records a block read failure before checkout. Focused regressions now assert
that boundary for head and base markers, plus an output-stage failure for
regenerated markers. Checkout filters an omitted primary head from fetched
refs, and local clone discovery checks each configured origin URL.
The follow-up ran both generated proof suites (37 and 21 passing tests),
`npm run lint` (zero errors), `npm run typecheck:contracts`, the offline
research-finding walkthrough, and `git diff --check`.

Validation commands include `npm run lint`, `npm run typecheck:contracts`, and
`bash demo/research-finding-walkthrough.sh`. The test runner can select the
proof suites with `npm test -- primary-change-generated-blocks.test.mjs
primary-change-generated-files.test.mjs derived-artifacts.test.mjs`.
