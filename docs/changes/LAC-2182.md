# LAC-2182 — ARNODE22BUDGET-01

## Summary

Reduce repeated Node startup work in the offline hammer shell fixture.
Partition the same 76 scenarios round-robin across three test entrypoints,
backed by one shared suite, in the existing eight-worker pool.
Model a delayed wakeup in the permanently pending fixture
to exercise the last-second deadline boundary without 30 identical samples.
All original scenarios and assertions remain enabled.

## Interface changes

None to production. No changes to required checks, CI jobs, runner deadlines,
production retry allowances, sandbox isolation, or process-group cleanup.
Selecting only `hammer-self-rebase.test.mjs` now runs the first shard;
select all three entrypoints for the complete subset, as documented in
`CONTRIBUTING.md`. Test names identify the shard and each entrypoint reports
its shard index and registered case count. Default `npm test` still discovers
every case. There is no priority scheduling guarantee.

### Final rescue review

The LABELGATE status fixture records the requested launch IDs and checks them
after dispatch returns, so the production status-probe catch cannot swallow
its assertion. Simulator retryable-read trace labels now use the executor's
actual failure detail rather than predicting a failure from the recipe. The
existing recovery oracle also checks those observed labels.

The six-hour fixture deliberately retains its remote synthetic holder. The
shorter `merge-lease reconcile releases dead-owner-pid holder without calling gh`
and `merge-lease acquire reclaims stale dead-owner-pid holder during wait`
cases cover local PID liveness; the separate fixed-ceiling test covers polling.
Keeping these responsibilities separate avoids thousands of redundant host
process-table probes without dropping the local-holder assertions.

### Fixture and runner changes

- The simulator stores deeply frozen synthetic events and reuses one
  point-in-time array per ledger revision. The production executor still
  reads and folds the ledger and handles simulated read failures. Its
  synthetic repository uses an explicit empty exclusion list. In the first
  pre-change CPU profile, repeated ledger read clones accounted for at
  least 8.0 seconds of sampled time. Repeated config-key construction for
  executor creation accounted for another 3.7 seconds.
- The common idle-load fixture injects an ordinary function for cases that
  only need idle readings. It retains per-case restoration and the special
  host-load case. A `node:test` method mock was recording every call and
  stack in hot loops. Tests that explicitly inspect or override load
  samples continue to use their own mocks.
- The permanently UNKNOWN hammer fixture observes the initial state and
  models a delayed wakeup one second before expiry. The existing no-write,
  no-merge and lease-release assertions still run. New assertions pin the
  observation times and the unchanged deadline. The sibling prepredicate
  fixture uses the same clock jump. The REST request-budget fixture still
  exercises and counts each real polling iteration.
- The reviewer-arm fixture resolves Python once per file, still launches
  the real synthetic child, and advances the Node timer 1,600 ms before
  the child can settle. The separate real timeout and child-kill case
  retains its original assertions.
- The suite runner reads native file dequeue and completion events over
  its existing coordinator process boundary. At its deadline it prints
  the active files and the queued count before removing the sandbox.
  A deadline regression asserts the exact held fixture file and sandbox
  cleanup. The eight-worker bound, test discovery, process isolation,
  required hosted Node versions, 900-second deadline and group signalling
  remain in force.
